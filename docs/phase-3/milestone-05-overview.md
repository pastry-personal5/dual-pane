# P3-M5: Model tabbed workspace state

Status: Done

This milestone adds the Qt-free state and command boundary for independent Browser tabs, session-only history, Favorites editing, location-shared sort, multi-selection, and safe Folder Items refresh. It prepares the state consumed by the [tabbed desktop UI](phase-3.md#p3-m6-deliver-tabbed-browser-ui) without delivering that UI.

## Scope and fixed inputs

Follow the [P3-M4 interaction contract](milestone-04-overview.md#decision-sources-and-consumers), [product behavior](../product-behavior.md), [GUI rules](../ux-gui.md#planned-phase-3-gui-decisions), [P3-M2 storage contract](milestone-02-architecture.md), and [architecture boundaries](../architecture.md#3-boundary-ownership). Each Browser must always have one active tab. Tab history, selection, cursor, range anchor, and scroll restoration are tab-local; sort memory is shared by byte-exact location. A new navigation after Back drops the Forward branch. A failed read leaves the last successful Folder Items and its summary intact.

In scope: domain Browser/Tab/Favorites values and invariants; application commands, events, outputs, and request identity; integration with existing settings values and Favorites records; all eight sort modes and the metadata needed by them; tab-local selection and refresh reconciliation; and the minimal adapter and desktop runtime changes needed to keep the current two-Browser window working while the new boundary is introduced. The implementation approach is in the [architecture plan](milestone-05-architecture.md).

Out of scope: Browser Tabs Strip and Sidebar controls, visible sort controls and new columns, shortcut wiring, and accessibility behavior (P3-M6); file-operation intents and execution (P3-M7/P3-M8); saving and restoring workspace sessions or migrating stored filter fields (P3-M9); and native file-system watches (P3-M10). P3-M5 can accept an affected-location invalidation as an application input, but it does not create watcher events or file-operation jobs. It does not change the existing action IDs or add a dependency without the approval required by [AGENTS.md](../../AGENTS.md#dependencies-and-licensing).

## Completion checklist

- [x] Domain Browser and Tab state has stable tab identity, ordered tabs, exactly one active tab per Browser, a clean last-tab replacement, and session-only Back/Forward history. Tests cover creation, activation, reordering, closure, branch truncation, failed navigation, and independent Browsers.
- [x] Tab-local view state holds selection, cursor, range anchor, and a UI-neutral scroll restoration hint supplied through an explicit application input. Tests cover the [decided gestures](../ux-gui.md#selection-and-file-commands), including no-anchor Shift gestures, Command-click deselection, Command+A, right-click, plain movement collapse, and tab/history switching.
- [x] Qt-free Favorites state applies group and item create, rename, reorder, move, and delete commands while preserving stable IDs, one-level order, byte-exact targets, exact-text uniqueness, rejection of empty or whitespace-only names, intentionally empty collections, and the [launch-validation distinction](../product-behavior.md#favorites). A target-probe result applies only when it still matches the item's ID and target. Accepted edits use the existing durable records and report save failures.
- [x] One application Workspace owns both Browser tab sets, Favorites, and effective settings. Commands and outputs identify the affected Browser and tab; reads and cancellation are tokenized per tab and obsolete results cannot change a newer tab, location, sort, or listing. The runtime provides bounded per-tab read admission without making the GUI thread wait.
- [x] Name, Type, Date, and Size ascending/descending reads use the P3-M2 location-shared sort choice. Tests cover default and explicit Name ascending, 100-location LRU behavior, two tabs sharing one location, folder-first order, unknown metadata, symlinks, and exact-name tie handling.
- [x] Manual refresh and affected-location invalidation can refresh all matching open tabs, including inactive tabs in both Browsers. A successful refresh reconciles selection and cursor by exact entry identity, retains a matching scroll hint, and emits valid row changes; a failed refresh keeps the last successful view and error state. Tests cover superseded, cancelled, failed, and out-of-order results.
- [x] The existing desktop window still starts and browses through the revised boundary; no planned P3-M6 controls are made interactive early. Relevant application, adapter, runtime, and temporary-directory tests exercise the new request and result routing without real user paths.
- [x] Directly affected docs are current, including any implementation decisions or changed handoffs. `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `make check` pass before P3-M5 is marked Done.
