# P3-M6: Deliver tabbed browser UI

Status: Active

This milestone connects the P3-M5 tabbed Workspace to the macOS desktop interface. Both Browsers gain interactive tabs, history, Sidebar Favorites, folder sort and summary controls, and the agreed focus and selection behavior. The [architecture plan](milestone-06-architecture.md) describes the implementation boundary; this checklist defines completion.

## Scope and fixed inputs

Follow the [P3-M4 interaction contract](milestone-04-overview.md#decision-sources-and-consumers), [P3-M5 state and request contract](milestone-05-architecture.md), [planned GUI rules](../ux-gui.md#planned-phase-3-gui-decisions), [planned containment](../ux-information-architecture.md#planned-phase-3-containment), [canonical names and action IDs](../ux-terms.md), and [architecture boundaries](../architecture.md#3-boundary-ownership). Keep the P3-M2 settings and Favorites storage format and existing action IDs compatible. The application owns tab, Favorites, selection, and sort decisions; widgets show those decisions and submit UI-neutral gestures.

In scope: tab creation, activation, closure, drag reordering, labels and full-path descriptions; Back, Forward, Up, and manual Refresh; Sidebar Favorite Group and Item editing, movement, launch target probing, and activation; six Folder Items columns, including native item icons, the [Relative Date age color](../ux-gui.md#folder-items-fields-and-display), eight direct sort buttons, responsive hiding, Folder Pane summary, and the narrow-Browser overlay; multi-selection, cursor, scroll, focus, keyboard access, accessibility, and command enablement for the controls delivered here. The Path Edit Control continues to display the confirmed path without accepting typed navigation. Add the Notices Button, current-session error messages, and the explicit storage-recovery action according to the [Notices handoff](milestone-06-architecture.md#notices-handoff). The separate Settings window and shortcut editor remain future work; the existing disabled Settings control does not become the storage-recovery entry point.

Out of scope: file-operation commands, inline file-name editors, Operation Panels, and operation Notices (P3-M7/P3-M8); saved tab-session restoration, routine Notices startup opening and its preference (P3-M9); and native file-system watching (P3-M10). Actionable storage errors open Notices at startup in M6. Do not add a dependency or build tool without the approval required by [AGENTS.md](../../AGENTS.md#dependencies-and-licensing).

The [2026-10-02 owner decisions](changelog.md#2026-10-02--p3-m6-interview-decisions) also put these in scope: replacing the kind-only Type sort key with the displayed Type text, the eight-tab limit per Browser, root volume labels, and the approved `jiff` dependency in `dual-pane-adapters` for local-time formatting. The [third plan review](changelog.md#2026-10-02--p3-m6-third-plan-review) settled cursor movement, single-Item activation, Favorite editor and click behavior, shortcut suppression while editing, the unbound `CloseWindow`, and the headerless Folder Items List.

Verify with automated tests first. If an automated check fails or cannot establish a checklist item, notify the owner, who decides how that item is verified; the implementer does not decide an exception.

## Completion checklist

- [ ] Each Browser renders its ordered tabs and active tab independently. New Tab, tab activation, close button, `Command+T`, `Command+W`, and drag reordering use the P3-M5 commands; closing the final tab shows a clean Home tab. Labels, full-path tooltips and accessibility text, hover-only Close Tab Buttons, and nearest-right-then-left activation match the GUI rules. Each Browser holds at most eight tabs; at the limit New Tab and `Command+T` are disabled and the New Tab Button tooltip names the limit. Tabs shrink and elide labels without scrolling, and a root tab shows the volume name, falling back to `/`. A tab dragged outside its Browser stays in place. Tests cover both Browsers, same-name tabs, the domain tab limit, and the root label.
- [ ] Back, Forward, Up, Favorite activation, `Option+Left Arrow`, `Option+Right Arrow`, and `Command+R` target the correct active tab. The Path Edit Control remains read-only, displays that tab's confirmed path, and does not receive keyboard focus. Disabled navigation controls reflect available history and parent location; pending, failed, and superseded reads leave the last successful view and summary paired with its confirmed path. Refresh and navigation failure feedback stays visible without replacing that listing. Tab and history switches restore matching selection, cursor, and scroll.
- [ ] Sidebar Favorites render ordered groups and items from application output. Editing controls stay disabled while settings load or fresh-profile seeding waits for its probe, and the application reports a not-ready rejection for any edit that still arrives. Group creation, inline rename, menu movement and deletion, Item addition from the active folder, inline alias edit, pointer-only Item Context Menu, drag reorder and cross-group move, and Item activation all reach application commands. Adding an Item whose alias already exists in the group adds nothing and shows the brief inline “Already in this group” cue without a Notice. Rejected empty, whitespace-only, duplicate, or stale edits leave the committed hierarchy unchanged and produce inline feedback without adding a Notice. Editors follow the [Return, Escape, and focus-loss rules](../ux-gui.md#sidebar-favorites), New Group starts as an empty draft row, and a single click opens a Favorite Item and focuses the Folder Items List. An accepted edit remains in memory if its save fails, with recoverable storage feedback. Tests cover cross-group duplicate aliases and deletion of a group with children.
- [x] Launch probes run off the GUI thread after Favorites have loaded or been seeded. A completed unavailable result removes only the still-matching Item, requests a durable save, and adds a Notice naming it; failed or cancelled probes cannot prune Favorites. Tests cover edits or deletion while a probe is in flight, settings-load failure, and an intentionally empty collection.
- [ ] Folder Items show the Item Icon Column, Name, Type, Relative Date, Exact Date, and Size in the specified order and formats, with no header row and automatic widths. Native icons load off the GUI thread without delaying rows, and a missing icon never blocks the listing. Unavailable metadata shows `—`. Type shows `[DIR]`, `[LNK]`, the lowercase extension, or blank, and Type sort uses that displayed text in place of the P3-M5 kind-only key. Folders, including links to folders, show a blank Size and are excluded from totals; relative dates show `now` and `N min`; sizes below 1 KB show whole bytes. Exact dates use local time through `jiff`. Row #2 shows the last successful visible listing's count and selection count at the left and, right-aligned, `selected / total` or the total, each non-recursive known-size or `—`. The eight direct sort controls show the effective location-shared choice and update every open tab at that byte-exact location, including inactive tabs. A delayed sort click cannot change another tab's remembered choice. Responsive column and control hiding follows the specified order; the `Expand` overlay appears below 280 pixels without consuming commands.
- [ ] Relative Date paints black text over the [age-colored background](../ux-gui.md#folder-items-fields-and-display). Elapsed ages at one hour or less, one day, seven days, 30 days, and 365 days or more map to strip positions 0, 0.25, 0.50, 0.75, and 1, with linear interpolation and clamping between them. Future timestamps use position 0; missing timestamps show `—` over neutral light gray. The background dims immediately when its Browser is inactive or the window loses focus, while the age uses the listing's captured time and remains stable until reload. Selection and focus stay apparent. Qt-free tests cover every anchor, interpolation within every segment, clamping, missing metadata, and a reload that advances age without changing rows; native verification covers the painted text and selected, inactive, and focused rows.
- [ ] Mouse and keyboard selection match the planned Command-click, Shift-click, Shift-arrow, Command+A, right-click, and plain-movement rules. Movement starts from the cursor even with no selection. Return and Right activate only a single selected Item, never an unselected cursor row; tests cover a Command-click that leaves one Item selected and the cursor on another row. Qt row selection, current index, and scroll reflect application state without feedback loops or retargeting after a tab switch or row delta. Browser focus entry activates that Browser; `Option+F`, Full Keyboard Access traversal, tab and Favorite arrow/Return behavior, and text-editor shortcut priority, which leaves only `Command+Q` active, work without changing the other Browser's view state.
- [ ] Delivered controls have the canonical accessible names, useful full-path descriptions, tooltips, keyboard access where specified, and visible enabled states. `NewTab`, `CloseTab`, `NavigateBack`, `NavigateForward`, and `RefreshFolder` join the action catalogue with their documented defaults. Every delivered shortcut, including `Option+F`, `Command+Q`, and the sort actions, binds from the effective settings and rebinds after load or reset. Schema version 3 moves the existing workspace `Command+W` binding from `CloseWindow` to `CloseTab` without reusing or renaming either ID; `CloseWindow` retains its meaning. The workspace `Command+W` closes a tab, `Command+Q` quits, and a focused Notices window closes with `Command+W`. Tests check the effective bindings for fresh, v2-upgraded, v1-to-v3 chained, and customized settings, with no shortcut collisions and `CloseTab` bound.
- [ ] The Notices Button opens a current-session window that shows storage and Favorite probe failures and automatic removals without blocking browsing. Actionable storage failures open Notices even at startup. A storage error offers Reset Settings whenever a settings worker exists. Reset requires explicit confirmation with Cancel as the default, warns that current-session changes will be replaced, preserves the failed database, reloads fresh settings after success, and reports success with the preserved database's location, or reports failure. A cancelled reset leaves the database untouched. Reset remains available after a database-open failure and cannot apply an older queued save afterward. Tests cover load, save, worker-start, corrupt/newer-schema, reset-preservation, stale-save, and reset-failure paths without real user data. Later milestones add operation and restoration messages and the routine startup preference.
- [ ] Qt-free adapter and desktop-session tests cover stable-ID command routing, rejected Favorites edits, sort/tab changes during input, inactive-tab updates, and selection/scroll restoration. Native macOS verification covers rendered tabs, six columns with native icons, Sidebar editing, drag gestures, focus and Full Keyboard Access, responsive hiding, accessibility names, and both `Command+W` window contexts. Use automated tests first; if an automated check fails or cannot establish part of this item, notify the owner and leave it unchecked until the owner decides how it is verified. All file-system tests use temporary directories.
- [ ] Directly affected product, UX, README, and plan docs reflect the delivered behavior. `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `make check` pass before P3-M6 is marked Done; any unavailable gate leaves this item unchecked with the exact blocker recorded.

## Acceptance evidence

Status on 2026-10-02: the original four planned steps and the later Relative Date color work are implemented, with automated checks passing. The color painting still needs native visual verification. Only the launch-probe item is checked. Every other item includes native Qt Widgets behavior that no automated test establishes. Per the verification rule above, those items stay unchecked until the owner decides how to verify them.

Automated evidence:

- **Domain:** `BrowserTabs` limit and shared Type text in `browser.rs` and `tests/listing_sort_order.rs`.
- **Application:** projections, tab-addressed gestures, delayed-sort rejection, inactive-tab sort, typed Favorites rejections, cross-group duplicates, group deletion with children, launch probes, Notices, reset and stale saves in `tests/tabbed_interface.rs` and `tests/two_browser_workspace.rs`.
- **Adapters:** six-column formatting with `jiff`, summary, selection gestures, single-Item activation with the cursor on another row, tab labels with the root volume name, toolbar and sort routing, scroll restoration, Favorites routing and inline duplicate cue, Notice wording, and rebinding after a load in `tests/tabbed_view_models.rs` and `format.rs`.
- **Desktop session:** a session without a settings worker (`a_session_without_storage_settles_as_failed`), inactive-tab sort, restoration, delayed gestures, scroll reports that do not activate a Browser, probes through the runner, and real-SQLite load, corrupt and newer-schema failures, reset preservation, stale save, reset failure, and save failure in `browser_session.rs`.
- **Runtime and storage:** Favorite probes on the probe lane in `runtime.rs`; fresh, v2-upgraded, v1-to-v3 chained, and customized effective bindings in `settings_storage.rs`; Qt key sequences in `workspace_bridge.rs`.
- **Native icons off the GUI thread:** a Qt 6.11.2 spike on this machine reported `ThreadedPixmaps` for the Cocoa platform and rendered a native icon to a `QImage` on a worker thread.
- **Relative Date color:** `format.rs` tests every age anchor, segment midpoint, and clamp; `browser_boundary.rs` checks missing metadata, a reload with unchanged rows, and the listing time retained across tab switches. The desktop model exposes the Relative Date color role and emits a column update on a same-row reload. The delegate uses the existing pane and window active state, and the highlight controller requests a viewport repaint when it changes. A Qt 6.11.2 color probe measured active endpoints `#E8B0B0` and `#CCB0E8` with at least 10.22:1 black-text contrast, and dimmed endpoints `#C29999` and `#AD99C2` with at least 7.68:1 contrast. The dimmed color had lower luminance at each of 10,001 sampled positions.
