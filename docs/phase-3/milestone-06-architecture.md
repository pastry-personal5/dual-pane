# P3-M6 architecture

Status: Planned

P3-M6 turns the P3-M5 Qt-free Workspace into two independently interactive desktop Browsers. The [overview checklist](milestone-06-overview.md#completion-checklist) is the acceptance contract. Every new tab, Sidebar, toolbar, and Notices surface follows the [MVVM and command rules](../architecture.md#architectural-styles). Product and interaction rules stay in the active [product](../product-behavior.md) and [GUI](../ux-gui.md#planned-phase-3-gui-decisions) documents.

## Ownership and affected modules

| Ring | Planned change |
|---|---|
| Domain | Keep the existing tab, selection, Favorites, and sort invariants. Add only a missing UI-neutral query if presentation cannot derive a required fact from existing state. |
| Application | Expose immutable ordered tab, active-tab, Favorites, sort, history-availability (from `Workspace::can_go_back` and `can_go_forward`, which count a pending Back or Forward as taken), and summary inputs for rendering and command enablement. Emit typed rejections for editable Favorites commands so the UI can distinguish invalid names, duplicates, stale IDs, and no-op edits. Keep commands and result validation in `Workspace`; do not make Qt inspect its private state or infer policy from widget contents. Route launch Favorite target probes, settings recovery, and their results through typed work requests/events. |
| Adapters | Extend the input controller with UI-neutral tab, Favorite, navigation, sort, refresh, and selection events carrying stable IDs or observed entry identity. Extend presenters with tab-strip, Sidebar, toolbar, summary, column, and status view models. Formatting and labels belong here; validity and availability come from application state. |
| Desktop | Update `browser_session.rs`, `folder_items_list_model.rs`, and the CXX-Qt bridge to relay events and apply view models. Evolve the current single-column list-model bridge into a multi-column Folder Items model with correct row and column notifications. Update the private Qt Widgets in `desktop_window.cpp` for the interactive strip, Sidebar, columns, toolbar, focus, accessible properties, and Notices. Reuse `runtime.rs` for off-thread reads, settings saves, and bounded result delivery. Its serialized probe lane already checks the fresh-profile Screenshots folder through `location_probe.rs`; route Favorite target probes through the same lane. |

## State projection and event flow

P3-M5 outputs identify tabs but do not yet provide an ordered tab-strip snapshot, full Sidebar presentation, or all toolbar availability. Add explicit application projections or outputs for those surfaces so a newly constructed window and any later state change render from the same source. A tab view includes stable tab ID, confirmed location or pending target, folder-name label, loading/error state, and whether it is active. The visible Browser projection includes the effective sort, history/parent availability, rows, selection, cursor, scroll hint, and the location associated with the last successful summary. Favorites projections retain stable Group and Item IDs and order. Projection delivery must distinguish inactive-tab updates from the active tab's widgets, while keeping inactive state ready for instant activation. Keep row deltas and metadata-only cell changes explicit so a listing update does not reset the whole model unnecessarily. Same-folder reloads already report one minimal `RowChange`, and `BrowserViewModel::update_from` turns it into Qt insert, remove, and `dataChanged` notifications; the multi-column model extends those notifications to every column.

Qt signals become `UiEvent` values, then application commands through the input controller. Tab clicks and Close Tab Buttons carry the exact tab ID; drag results carry that ID and destination position. Favorite controls carry stable Group or Item IDs, not row numbers. Folder Items gestures carry the observed tab, entry identity, and current row so the reducer can reject a stale widget event after a tab switch. A sort gesture carries Browser side, observed tab ID, confirmed byte-exact location, and requested `SortSpec`; the application validates the context before changing shared sort memory and refreshing all matching tabs. Refresh and other Browser-specific gestures receive the same stable-tab check where a queued Qt event could arrive after activation changed. Native settings, launch probes, and directory results return as typed events through the existing serialized GUI-owner path. Never block that path on a scan, save, probe, or dialog.

## Widgets, focus, and visible state

Replace each inert Browser Tabs Strip label with ordered tab controls plus New Tab Button. The private Qt view handles hover-only Close Tab Button visibility, drag insertion feedback, full-path tooltips and accessible descriptions, arrow-key focus movement, and Return activation. It does not own the active tab. Tab changes apply the active tab's read-only, non-focusable Path Edit Control, listing model, status, selection, cursor, and scroll together. The path control displays the confirmed location and does not submit navigation. Capture the outgoing viewport hint with the explicit P3-M5 input before a tab or history transition; when a row delta or tab view arrives, map the returned entry anchor and offset to the current viewport, clamping only when the anchor disappeared. Guard programmatic Qt selection and current-index updates against emitting a second user command.

Focus entry into any focusable Browser child emits Browser activation before handling a Browser-specific gesture. `Option+F` moves focus to the other Folder Items List while preserving both views. Register delivered New Tab, Close Tab, Back, Forward, and Refresh actions under their reserved canonical IDs. Give `CloseTab` the workspace `Command+W` default, remove that default from `CloseWindow`, and migrate an older saved `CloseWindow` `Command+W` binding to `CloseTab` in the schema version 3 SQLite transaction that adds its catalogue row. Schema version 2 already exists: it gave `NavigateParent` its `Command+Up` default and made a stored NULL key mean an unbound action. Preserve any other valid, nonconflicting `CloseWindow` override and the ID's close-window meaning. Validate the resulting catalogue for context-relevant collisions and test fresh, upgraded, and manually customized records. At the focused window boundary, workspace `Command+W` closes the active tab and Notices `Command+W` closes Notices. `Command+Q` remains application Quit. Inline name editors consume editing keys and suppress file-manager shortcuts during editing. Plain Tab follows Full Keyboard Access traversal; only the approved drag and context-menu interactions lack keyboard equivalents.

The Folder Items model exposes six display columns from the same immutable entry snapshot: the Item Icon Column, then the five text fields. Native icons follow the [GUI rule](../ux-gui.md#folder-items-fields-and-display): resolve each icon off the GUI thread, deliver it as image data through the bounded result path, cache it per Browser by item identity, and update only that row's icon cell. Qt's `QFileIconProvider` provides macOS native icons without a new dependency; if it cannot run off the GUI thread safely, raise the alternative with the owner before adding Objective-C++ or any build change. Relative and exact dates format the same timestamp; relative text changes on reload, not by timer. The domain derives each Entry's Type text (`[DIR]`, `[LNK]`, lowercase extension, or blank) through one shared function that both `sort_entries` and the presenter use, so displayed Type and Type sort cannot diverge. The presenter formats date, size, and summary text, including unknown totals and blank folder sizes; worker metadata remains optional and non-recursive. Exact Date conversion to local time uses the approved `jiff` crate in `dual-pane-adapters`. The view hides Size, Exact Date, Relative Date, then Type as its Browser narrows, hiding the corresponding sort pair when a field disappears. The Name column and its pair remain while usable. Below 280 pixels, a semi-transparent `Expand` layer covers only that Browser. Toolbar enablement and the active sort indication follow the projection, including pending/failure states.

The Sidebar renders the application-owned Favorites order. Inline editors submit draft text and keep focus when the application rejects a name; a typed rejection identifies invalid text, duplicate text, or a stale target without requiring the widget to duplicate validation policy. These synchronous validation errors stay inline and do not add Notices entries. Group menu actions and Item context actions use one input boundary. Native drag-and-drop transports stable Item identity and destination Group/position; it cannot mutate Sidebar order directly. A cross-group move that would duplicate an alias reports rejection and preserves the original position. After the settings snapshot loads or fresh defaults seed, the runtime probes launch Items off the GUI thread and submits each outcome as `FavoriteProbeOutcome` (available, unavailable, failed, or cancelled); only `Unavailable` removes an Item. No probe runs against an uninitialized or failed settings load. A completed unavailable probe adds a Notice naming the removed Item and requests its durable save. Saving accepted edits uses the P3-M2 settings service; visible errors do not roll back accepted in-memory edits, and the UI must not claim the edit is durable until the relevant save succeeds.

## Notices handoff

The Main Toolbar gains a Notices Button and an auxiliary Notices window with accessible title, open, focus, and `Command+W` close behavior. M6 records current-session storage errors, Favorite probe failures, and automatic Favorite removals as nonblocking messages in application-owned state or output and renders them in Notices. Preserve the storage gateway's typed failure category, operation, save revision, and recovery context through `WorkspaceSession`. Load failures already arrive as `Event::SettingsLoadFailed` with a `SettingsFailure` category (worker unavailable, unavailable, corrupt, or unsupported schema), and the worker reports typed `SaveFailed`, `Reset`, and `ResetFailed` results; M6 carries the save and reset categories into application events. The application never saves while settings are loading or after a failed load, so a damaged database stays untouched until an explicit reset. An actionable storage error opens Notices at startup, independent of the later routine-notice preference. The UI must distinguish an accepted in-memory edit from a failed durable save and must not discard a failed-load error while showing compiled defaults.

The Notices storage-error entry offers Reset Settings. A separate confirmation defaults to Cancel and sends the application command only after explicit Reset. The settings worker already stays available after a failed open and reopens storage lazily, and its reset moves the failed database and SQLite sidecars aside, restores them if any move fails, and never substitutes an in-memory database. M6 adds the confirmed command, the reload after reset, and the application's handling of its results. On success, load the new snapshot, replace effective settings and Favorites, invalidate older pending save results and queued snapshots, then launch-probe the fresh Favorites. Cancellation changes neither the database nor the effective settings. A failed preservation or replacement keeps the error visible and does not claim success. P3-M8 adds operation messages; P3-M9 adds session-restoration messages, routine startup opening, and the persisted startup checkbox. No file-operation command is enabled before P3-M7/P3-M8.

## Sequence and verification

1. Add complete application projections and adapter events/view models, with Qt-free tests for stable-ID routing, typed edit rejection, enablement, shared sort, Favorites edits, and inactive-tab updates.
2. Wire tab and navigation controls to the existing desktop session; verify two-Browser independence, last-tab replacement, same-name tab descriptions, stale-result rejection, and scroll/selection restoration.
3. Wire Sidebar editing and launch probes, then six columns with native icons, summary, sort controls, and responsive layout. Keep saves, probes, and directory reads off the GUI thread.
4. Migrate shortcut bindings and wire focus, accessibility, native gesture handling, Notices, and confirmed storage recovery, including the failed-open worker path. Verify pointer, keyboard, drag, and narrow-window behavior on macOS, using automated tests first; then run the focused tests and full repository gate in the overview. If an automated check fails or cannot establish native behavior, notify the owner and leave that item unchecked until the owner decides how it is verified.

The owner approved `jiff` for `dual-pane-adapters` on 2026-10-02; this plan assumes no other new dependency or build tool. If another becomes necessary, obtain the approval required by [AGENTS.md](../../AGENTS.md#dependencies-and-licensing) before changing it.
