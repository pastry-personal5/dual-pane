# P3-M9: Persist and restore the workspace

Status: Planned

This milestone saves each Browser's tabs, active tab, and locations, the active Browser, and the workspace window's layout as a coalesced session snapshot. At launch it restores the layout and the restorable tabs, discards the rest with a Notice, and falls back to a clean Home tab. A slow settings load shows a Waiting Window and eventually times out to protected Home tabs. It also delivers the persisted Notices Startup Checkbox, the startup rule for opening Notices, and a Reset Settings that returns the workspace to its defaults. [Architecture](milestone-09-architecture.md) describes the approach; this checklist defines completion.

## Scope and fixed inputs

Use the [included product scope](../product-behavior.md#included-product-scope), the [session recovery policy](../product-behavior.md#session-recovery), [Notices and restoration feedback](../ux-gui.md#notices-and-restoration-feedback), [Browser Tabs Strip and navigation](../ux-gui.md#browser-tabs-strip-and-navigation), the [settings boundary](../architecture.md#6-error-settings-and-observability-boundaries), the P3-M2 [workspace-session handoff](milestone-02-architecture.md#workspace-session-handoff) and [storage lifecycle](milestone-02-architecture.md#storage-and-lifecycle), and the [P3-M4 handoff](milestone-04-architecture.md#contract-to-later-milestones). P3-M5's tab, history, and token rules and P3-M8's Notices rules stay as they are, except where the startup rules below narrow when Notices opens.

In scope: the session snapshot and its save requests; schema version 4 session tables; separate coalesced session saves and a final save at quit; one-time launch restoration with discard, active-tab, and fallback rules; damaged-session handling; retained locations for tabs that never confirmed one; focus on the restored active Browser; the window layout (frame, zoomed or full-screen state, and Sidebar Splitter and Browser Divider positions) with display fitting and a Waiting Window; a ten-second settings-load timeout with protected Home fallback and late-answer handling; Reset Settings returning tabs, the active Browser, and the layout to their defaults; the Notices Startup Checkbox and its stored preference; the startup period and its Notices opening rule; new Notice kinds; and removal of the unused filter field.

Out of scope: watching and live refresh (P3-M10); restoring Back/Forward history, selection, cursor, scroll, Notice history, or the Notices window's or Operation Panels' positions; resuming file operations; text filtering; a Settings window; and a shortcut editor.

## Decisions recorded 2026-10-03

| Topic | Decision |
|---|---|
| Slicing | One milestone with the ordered checklist below. |
| Discard rule | Owner decision. A restored tab is discarded when its first read completes with `ItemMissing`, `NotADirectory`, `PermissionDenied`, `PrivacyRestricted`, or `Unknown`. `Busy`, `Internal`, a cancelled read, or a read superseded by the person's own navigation never discards it. Recorded in the [session recovery policy](../product-behavior.md#session-recovery). |
| Restore display | Owner decision. Saved tabs and the active tab appear at once and read their folders, the active tab first. A tab is discarded when its result arrives. The nearest-right-then-left rule is applied at each discard, which yields the nearest surviving tab whatever order results arrive in. If a Browser's last tab is discarded, it gets a clean Home tab. Recorded in [ux-gui](../ux-gui.md#notices-and-restoration-feedback). |
| Fallback | Owner decision. Every fallback opens a clean Home tab at the user's home directory: no saved session, a failed settings load, no settings worker, a damaged session, or a Browser whose restored tabs were all discarded. This matches closing a last tab. The launch working directory, which macOS sets to `/` for a Finder or Dock launch, is no longer used at startup; this replaces the 2.0.0 launch behavior. Recorded in the [session recovery policy](../product-behavior.md#session-recovery). |
| Damaged session | Owner decision. Session rows that can be read but fail validation, including an invalid layout row, drop the whole session, add a routine Session Not Restored Notice, and leave settings, Favorites, and saving working. The plan also treats a missing layout row beside saved tabs as damaged, pending owner confirmation. A SQLite read failure that prevents validation follows the P3-M2 settings-load failure rule and blocks saves, so temporary storage failure cannot replace a valid session. |
| Discard Notices | Owner decision. Each discarded tab gets its own Notice naming its folder and reason, as each removed Favorite Item does. |
| Slow folders | Owner decision. A restored tab whose read never answers, such as one on an unresponsive volume, stays loading and is never discarded for being slow. |
| Window layout | Owner decision, which widens the [product scope](../product-behavior.md#included-product-scope) and a Phase 3 exit criterion. Relaunch restores the window's frame, its zoomed or full-screen state (full screen reopens in its own Space), and the Sidebar Splitter and Browser Divider positions. A frame that no longer fits the connected displays moves fully onto the display it overlaps most, or the main display, shrinking only if it must. |
| Window reveal | Owner decision. The workspace waits for the first settings-load answer for up to ten seconds before appearing at its restored or default layout. A separate, transient Waiting Window shows an animated loading state while the answer is pending. A fast answer skips it. |
| Load timeout | Owner decision. After ten seconds without an answer, show two Home tabs and a storage timeout Notice. A late success loads settings and Favorites, but does not restore tabs or layout and never enables session saves for that launch. The previous session remains available on the next launch; a deliberate Reset Settings can clear it. A late failure leaves the in-memory defaults and saving disabled. |
| Startup Notices | Owner decision. With the box unchecked, the first startup notice in the startup period opens Notices once, without focus. With it checked, only notices that offer an action open it (Reset Settings, journal Try Again); sweep failures are recorded silently, which narrows the P3-M8 rule for this case only. |
| Startup period | Owner decision. The period ends once the settings load, restored-tab reads, Favorite launch probes, and temporaries sweep have answered, or about five seconds after the workspace window appears. Notices about the person's own actions, such as an opening failure, are not startup notices and keep their usual rules. |
| Preference | Stored in the settings database and saved promptly, like a Favorites edit. Older databases and Reset Settings yield unchecked. After a failed settings load it changes only in memory, like every other setting. |
| Session storage | Schema version 4 adds session tables to the settings database. A separate session save job on the same worker is coalesced on its own and written in its own transaction that touches only session rows, so a session write can never roll back a Favorites edit, and the reverse. Reset is a barrier that drops both kinds of queued pre-reset save after a successful reset. |
| Saved content | Per Browser: its tabs in order with each tab's location, and the active tab. Also the active Browser and the window layout as typed values in logical points, not Qt's opaque geometry bytes. A tab's location is its confirmed folder, or the folder it was asked to open if it never confirmed one. Sort comes from the folder-sort memory. History, selection, cursor, scroll, and filter are never saved. |
| Save triggers | Opening, closing, reordering, or activating a tab; activating a Browser; a tab confirming a new location; a discard; the end of a window move or resize, a zoom or full-screen change, or a splitter drag; and a final save at quit. Saves wait for a successful settings load. The delay is the settings worker's existing coalescing. |
| One-time restoration | Restoration runs once, on the first settings-load answer or the ten-second timeout, and only replaces a Browser's untouched placeholder tab. A late answer after timeout loads settings and Favorites but cannot restore the saved workspace. The reload after Reset Settings never restores from the database or reopens startup Notices. |
| Reset Settings | Owner decision. A successful reset also closes every tab, leaving each Browser one clean Home tab, makes the Left Browser active, leaves full screen or zoom, and returns the window to its default size centered on its current display with the splitters at their default positions; the fresh database then saves this session. A failed reset changes none of it, and the confirmation says what a reset does. |
| Filter compatibility | Schemas 1–3 create no session or filter table, so no stored filter exists to migrate. `TabSnapshot.filter` is removed, which closes the P3-M4 and P3-M5 compatibility handoff. |
| Focus | Owner decision. After restoration, the restored active Browser's Folder Items List has keyboard focus, and the saved active Browser wins over any earlier focus event. |
| Verification | Automated tests first, then a human check at the end for what automation cannot cover. Do not launch the GUI from an agent session. |

## Completion checklist

Ordered by dependency; each later group builds on the earlier ones.

### Session state and restoration

- [ ] `TabSnapshot` loses its `filter` field. A Qt-free session snapshot is built from the workspace: each Browser's tabs in order, the active tab's index, the active Browser, and a reported window layout. A never-confirmed tab contributes its requested location. The builder returns no snapshot until a layout is reported and never yields a Browser with zero tabs.
- [ ] A Qt-free `WindowLayout` holds the normal frame in logical points, the normal, zoomed, or full-screen state, and both splitters' sizes. A layout command from presentation replaces it and requests a session save, and the close event's report is handled before quitting is accepted.
- [ ] No Browser reads a folder before the first settings-load answer or timeout unless it was navigated. The desktop no longer navigates both Browsers at start, and `BrowserStartup` no longer carries the working directory.
- [ ] Restoration runs once per launch and acts only on untouched placeholder tabs; a Browser navigated before the load keeps its tab and is refreshed with the loaded sort. A saved session replaces the placeholder tabs with fresh tab IDs in saved order, through a domain constructor for an ordered tab list that refuses more than eight tabs, an empty list, or an out-of-range active index. It applies the saved active tabs and active Browser and starts every restored tab's read, the active tab first.
- [ ] A restored tab is discarded only by a failure result of its restoration read, for the five decided error kinds. A re-read the workspace starts on its own, such as after a `LocationInvalidated`, keeps the restoration mark; a read the person asks for ends it. Tests cover each kind, `Busy`, `Internal`, cancellation, a read superseded by navigation, an invalidation re-read, a closed tab, and success.
- [ ] Discarding an active tab activates the nearest surviving tab on the right, then on the left. Exhaustive tests for small tab sets and generated result orders for larger sets show the final active tab equals the policy's answer. Discarding a Browser's last tab creates a clean Home tab, as closing a last tab does.
- [ ] Each discarded tab adds its own Tab Discarded Notice naming its folder and reason. A restored tab whose read has not answered stays loading and is never discarded by time.
- [ ] A tab that never confirmed a location keeps its requested location after a reader failure, for its Browser Tabs Strip label, the session snapshot, and `Command+R`.
- [ ] With no saved session, a failed settings load, or no settings worker, each untouched placeholder tab navigates to Home. A damaged session does the same and adds the Session Not Restored Notice. After ten seconds without a settings-load answer, both untouched placeholders navigate to Home, the workspace opens at its default layout, and a storage timeout Notice explains that the prior session is protected and this launch's workspace changes will not be saved.
- [ ] A late settings success after the timeout applies settings and Favorites, including their usual launch probes, but never replaces visible tabs, active Browser, or layout and never enables session saves for this launch. A late failure keeps in-memory defaults and storage writes disabled. Quitting after a timeout cannot send a session snapshot; Reset Settings is the only deliberate path that clears the protection and starts a fresh saved session. Tests cover each late outcome, navigation after timeout, quit, and reset.
- [ ] A successful Reset Settings closes every tab and leaves each Browser one clean Home tab, makes the Left Browser active, cancels the old reads, and asks presentation for the default layout. Running operations continue and inline editors on closed tabs close. The reload restores nothing from the database, opens no startup Notices, and then saves the Home tabs and current layout. A failed reset changes none of it.
- [ ] Session saves are requested after each decided trigger and once after a first restoration or fallback that completed from a settings-load answer and has a layout report, only while settings are loaded and the launch has not timed out. A damaged-session fallback therefore replaces the invalid rows without touching settings or Favorites; a timed-out fallback never overwrites the prior session. Quitting sends a final worker job even when there are no dirty settings and flushes the newest session and settings snapshots independently. A test proves that quitting during restoration saves the restored tabs that are still pending.
- [ ] A property test shows that restoring a saved session yields that session minus its unrestorable tabs, with the policy's active tabs, the saved active Browser, and the saved layout. A Browser left with no restorable tab instead has one Home tab.

### Notices at startup

- [ ] `SettingsState` holds the hide-at-startup preference. Its command saves promptly, older databases and Reset Settings yield unchecked, and a failed load keeps changes in memory only. The checkbox cannot be changed until the first settings-load answer, so a late load cannot erase an earlier toggle.
- [ ] The startup period ends on the earlier of its launch work answering and an elapsed event from the desktop, and tests cover both. A startup notice is one produced by launch work: session restoration or timeout, a Favorite launch probe, the temporaries sweep, or the launch settings or journal result. With the box unchecked, the first startup notice in the period requests one Notices opening; if it arrives before the preference loads, the request waits for the load, except that a timeout opens Notices once the workspace appears. With the box checked, only startup notices that offer an action open Notices. A failed load, including a missing settings worker, leaves the box unchecked, so its Notice opens Notices. Notices from the person's actions keep their rules in both cases.
- [ ] New `NoticeKind` variants for a discarded tab, a damaged session, and a settings-load timeout have presenter wording. The timeout Notice explains session-save protection and opens Notices after the workspace appears, without focus. Tab Discarded and Session Not Restored do not offer Reset Settings; the timeout Notice does not offer it while the load is pending.

### Settings storage

- [ ] Schema version 4 adds session tables, including one window-layout row. Migration from versions 1, 2, and 3 preserves every existing record and loads with no session and the preference unchecked; a newer version stays unsupported.
- [ ] A session round-trips byte-exact non-UTF-8 locations, tab order, active indexes, the active Browser, and a layout in each window state. Its save replaces every session row in one transaction, never touches bindings, folder sorts, Favorites, or the preference, and a failed write leaves the previous session intact.
- [ ] Session rows that can be read but fail validation load as a damaged session without failing the settings load: wrong Browser count, orphan rows, gaps in positions, zero or more than eight tabs, an out-of-range active index, no single active Browser, an undecodable location, a missing or invalid layout row, a non-positive frame size, an unknown window state, or a negative splitter size. No session rows yield the default layout. The settings remain saveable, and the next session save replaces damaged rows. A SQLite read failure instead fails the settings load and preserves the stored session; tests cover both paths.
- [ ] The settings worker coalesces session saves separately from settings saves and reports their results under a separate revision. Shutdown flushes both within the existing timeout, including when only a session changed. A successful Reset Settings drops both kinds of queued pre-reset save, leaves the fresh database without a session, and allows only post-reset saves into it; a failed reset preserves the existing database and pending saves.

### Presentation

- [ ] The workspace stays hidden until the first settings-load answer or ten-second timeout, without blocking the GUI thread. Signal handlers are connected before settings work starts, including the synchronous no-worker answer. It then appears once with the restored or default layout: the fitted normal frame, requested zoom or full-screen state, and both splitters' sizes. A failed load, missing worker, or timeout reveals the Home fallback. A late answer cannot move the visible window.
- [ ] When a load is still pending after a short delay, a transient Waiting Window appears with a polished, indeterminate animation derived from the existing dark palette: two Browser shapes, a moving accent path, restrained easing, and a clear “Loading workspace” label. It paints and animates on the GUI thread without waiting for storage or adding a dependency; reduced-motion settings use a static state. The window is accessible as “Loading workspace”, provides Quit, never claims numerical progress, and closes when the workspace appears. The human check judges its visual quality, focus, and transition into normal, zoomed, and full-screen layouts.
- [ ] A Qt-free fitting function moves a saved frame fully onto the display it overlaps most, or the main display, shrinking it only when it does not fit. Tests cover a frame that fits, an unplugged display, a smaller display, an oversized frame, and no overlap.
- [ ] The window and both splitters report the layout at the end of each move, resize, zoom or full-screen change, or drag, and once more from the close event. The normal frame is the pre-zoom, pre-full-screen frame.
- [ ] On a successful Reset Settings, presentation leaves full screen or zoom, centers the default size on the window's current display, restores the default splitter positions, and reports the result. The Reset Settings confirmation says that open tabs close and the layout returns to its defaults.
- [ ] The bridge and widgets render restored tab sets, active tabs, and the active Browser. They show placeholder tabs as loading before restoration, remove discarded tabs without losing other tabs' view state, and move keyboard focus to the restored active Browser's Folder Items List.
- [ ] The Notices window renders the Notices Startup Checkbox with the text “Don’t show notices at startup” and the accessible name Notices Startup Checkbox. It shows the loaded preference, is disabled until the first load answer, and sends the command when toggled.
- [ ] The desktop sends the startup-period elapsed event about five seconds after the workspace window appears. A startup opening shows Notices without taking focus.

### Human check

Automated tests cover the application, storage, presenter, and bridge logic. What remains needs the native interface and a real relaunch, which an agent session does not do. After the automated gate, the owner checks:

- quitting with several tabs in both Browsers and relaunching restores their order, active tabs, active Browser, and focus
- a slow settings load shows the Waiting animation, keeps Quit available, and transitions directly to the restored workspace without a layout jump; a fast load does not flash the Waiting Window
- after ten seconds of an unanswered load, Home tabs and the timeout Notice appear without focus theft; a later answer leaves the visible workspace alone, and relaunch still has the saved session
- the Waiting Window's VoiceOver status and reduced-motion appearance are usable
- the window reappears without jumping at its saved frame, zoomed, or in full screen in its own Space, with both splitters where they were, and a frame left on an unplugged display moves onto a remaining one
- Reset Settings states its consequences, then closes the tabs, makes the Left Browser active, and returns the window, including from full screen, and the splitters to their defaults
- a removed or renamed saved folder is discarded with a Notice, Notices opens without focus, and the active tab follows the policy
- a disconnected volume's tab is discarded, and a damaged session falls back with its Notice
- the Notices Startup Checkbox persists across relaunches and suppresses routine startup opening, while a settings error still opens Notices
- the Notices Startup Checkbox's VoiceOver name and keyboard access
