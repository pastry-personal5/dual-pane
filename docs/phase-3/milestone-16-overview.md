# P3-M16: GUI polish and Preview Pane

Status: Planned

P3-M16 refines the Favorites controls and gives each Browser a compact, expandable Preview Pane. The pane starts as the Browser's one-line status presentation and expands into item content and details for the current selection without moving file I/O or image decoding onto the GUI thread.

## Scope and owner decisions

Use the existing [Visual layout and accessibility](../ux-gui.md#visual-layout-and-accessibility), [Sidebar Favorites](../ux-gui.md#sidebar-favorites), [Folder Items fields and display](../ux-gui.md#folder-items-fields-and-display), [P3-M9 session layout contract](milestone-09-architecture.md#layout-capture-and-restoration), and [P3-M12 visual rules](milestone-12-architecture.md). P3-M14 and P3-M15 remain earlier milestones; P3-M16 is planned only.

| Topic | Approved behavior |
|---|---|
| Favorite controls | Favorite Group Menu (three-dot) and Add Favorite Item (plus) buttons use `#A7ADB5` on `#24282E` normally, white on `#2F6D9A` on hover, white on `#245878` while pressed, `#6F757D` on transparent while disabled, and `#8A9099` on `#1B1D21` in an inactive Sidebar. Their button state remains visually distinct from the parent Favorite Group row and does not alter the existing actions, accessibility names, or pointer routing. |
| Preview placement | Each Browser places a Preview Pane below its Folder Items area, separated by its own draggable, vertically oriented splitter. The Folder Pane's Browser Status Bar is removed. |
| Collapsed state | The Preview Pane starts at one text-line height and renders exactly the steady-state or transient text that the removed Browser Status Bar would have rendered. It remains readable before the first successful listing and during loading, errors, monitoring, command feedback, and Quick Look failure feedback. |
| Expanded layout | When the person raises the Preview Pane above its one-line collapsed height, it displays two child panes: Item Content Preview at approximately two thirds of the available width and Item Details Preview at approximately one third. |
| Selected image | With exactly one selected regular image file and an expanded Preview Pane, Item Content Preview shows that image fitted within its available area without upscaling. Item Details Preview includes image width and height in pixels and byte size, plus normal available Item identity and metadata. |
| Other selections | The milestone does not add generic document, video, audio, directory, package, link, or multi-selection content renderers. The expanded pane reports a concise unavailable or multiple-selection state in Item Details Preview; it never presents a stale image from a former selection. |
| Lifetime and persistence | Preview requests are per Browser active tab and are invalidated on selection, tab, location, listing, or pane-collapse changes. A decoded result is accepted only for the current request identity. Each Browser's vertical splitter position is included in the existing saved window layout and restored subject to the same valid-geometry rules as the Sidebar and Browser Divider positions. |

In scope: the two Favorites button color treatments; per-Browser Preview Pane composition and accessibility; collapsed status projection; per-Browser vertically oriented splitter interaction and durable layout; selection-driven image preview and details; background image metadata/decode work with bounded delivery and stale-result rejection; focused temporary-file tests; native macOS visual and accessibility checks; and directly affected UX, architecture, README, and acceptance evidence updates.

Out of scope: a general built-in file viewer; text, media, PDF, folder, package, link, or multiple-item previews; changing Quick Look; a new user preference; changing file-manager selection, navigation, or operation behavior; changing Favorites data or command handling; a new third-party dependency or build tool; and reading, decoding, or scaling files on the GUI thread.

## Completion checklist

- [ ] The shared desktop styling gives the Favorite Group Menu Button and Add Favorite Item Button their approved foreground and background colors for ordinary, hover, pressed, disabled, and inactive-Sidebar states. Their parent row hover remains suppressed while either button owns the pointer, and existing actions, keyboard access, tooltips, accessible names, and resize behavior remain intact.
- [ ] Every Browser replaces Browser Status Bar with a vertically split Preview Pane below Folder Items. Its collapsed default is one line high and reproduces the former status text including blank-before-first-listing, concise summary, loading, error, monitoring, command-feedback, and Quick Look-failure precedence.
- [ ] The Preview Pane has named, keyboard-accessible Item Content Preview and Item Details Preview children. An expanded pane divides usable width about 2:1, respects narrow-Browser behavior, and does not obscure the Folder Items List, Missing Folder Overlay, tabs, path, toolbar, or Operation Panel Strip.
- [ ] Each Browser's Preview Pane splitter supports pointer and Full Keyboard Access interaction, restores a validated saved position after the workspace is laid out, and writes a coalesced session update after settled movement. Fresh and corrupt or out-of-range saved layouts use the one-line default without preventing ordinary window restoration.
- [ ] Expanding a Preview Pane evaluates only its Browser's active tab selection. A single selected regular image starts a cancellable, bounded background request using the exact native path; no display-path conversion can select a different file. Collapse, selection, cursor/listing revision, navigation, tab switch or close, file-operation refresh, and teardown invalidate obsolete work.
- [ ] The background image reader identifies supported image data, obtains dimensions and byte size, decodes a preview scaled for the current content area, and returns a typed unavailable or failure result. It neither blocks the GUI thread nor follows a link merely to render its target. Results are accepted only when their Browser, tab, selected entry identity, listing/selection revision, and pane request token still match.
- [ ] With an expanded Preview Pane and exactly one selected supported image, Item Content Preview shows a correctly oriented, aspect-ratio-preserving image without upscaling. Item Details Preview identifies the Item and shows its width × height and formatted byte size; unsupported, unreadable, disappeared, non-image, and multiple selections replace both the content and details appropriately and cannot leave stale pixels or dimensions.
- [ ] Qt-free tests cover preview request identity, selection/listing/navigation invalidation, accepted and late worker results, collapsed suppression, image and non-image projections, metadata formatting, and persisted layout validation. Desktop tests use only temporary directories and exercise byte-exact native paths, bad data, a disappearing file, large dimensions, both Browsers, tab switching, splitter persistence, and status projection. No test reads a user path.
- [ ] Native macOS verification records the macOS version and display scale, then covers all Favorite control states; both collapsed status panes; splitter drag and restored layout; single-image sizing and details; no selection, multiple selection, unsupported file, error, and rapid selection changes; narrow Browser; inactive Browser; keyboard traversal; and Quick Look coexistence.
- [ ] Affected product/UX/README documentation and acceptance evidence are updated. `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `make check` pass before P3-M16 is marked Done.
