# P3-M14 architecture: Basic Settings and Keyboard Shortcuts

Status: Planned

P3-M14 extends the existing Qt-free settings model through the established application, adapter, worker, and bridge path. The [owner decisions](milestone-14-overview.md#owner-decisions) define the Settings presentation and shortcut policy, including multiple shortcuts per action.

## Application and bridge

General adds no new preference. Reuse the existing `SetHideNoticesAtStartup` command and projection so its Settings and Notices controls remain synchronized. Reset submits the existing command after its existing explicit confirmation; close Settings when the person confirms. A failed reset reports through Notices. Settings remains unavailable during loading and after a storage failure, as P3-M13 defines.

Change `ActionBinding` from `Option<Shortcut>` to an ordered `Vec<Shortcut>` for each stable `ActionId`; its empty list means deliberately unbound. Keep one compiled default per action, represented as a zero- or one-entry list. A typed `SetActionShortcuts { action, shortcuts }` command atomically proposes the full replacement list, serving Add, Remove, and Restore Default. Application validation checks the supported key/modifier grammar, duplicates, all-action collisions, and the fixed reserved combinations in the owner table. Return typed rejection feedback identifying invalid input, a reserved combination, or the conflicting action. A rejected or unchanged proposal schedules no save. An accepted proposal updates in-memory state and schedules the existing settings-worker save.

Project the complete ordered lists, action identity, scope, and edit feedback through the adapter and bridge. The existing binding revision triggers `ShortcutBinder` to rebuild one `QShortcut` per assigned entry, preserving the current action scope and inline-editor suppression. The desktop translates key events into normalized proposals but never decides validity, collisions, or persistence. Keep the binder suspended during capture, including application shortcuts, and have the capture control accept shortcut-override and key events so a captured binding cannot invoke its action. Restore the binder when capture ends or Settings closes.

## Storage and presentation

Migrate the current single-row `action_binding` schema transactionally to a parent row per action and ordered child shortcut rows. A parent with no child records distinguishes deliberate unbinding from an absent action, which receives its compiled default. Convert each valid legacy shortcut to child position zero; preserve legacy NULL as an empty list. Keep the existing action-order collision recovery and per-action fallback for malformed legacy values. Seed fresh profiles with every action and its default list. The SQLite worker remains the sole durable authority; loading, whole-app reset, session storage, and failed-save behavior retain their existing guarantees.

Replace the P3-M13 placeholders in `SettingsWindow` with a visible Settings heading and General controls, then a scrollable Keyboard Shortcuts table. Use the existing dark content surface, restrained separators, neutral row hover, and blue keyboard-focus treatment. Each row presents its ordered shortcuts as individually removable entries, Add, an action-specific circled-i bitmap help button, scope, and Restore Default; an unbound row says “No shortcut”. General's two controls also receive item-specific help. Help opens a focusable anchored overlay with plain-language detail about the item's meaning, effect, and, for actions, scope and availability; dismissal returns focus to its button. The capture control describes the allowed modifier/key combinations, reserves bare Escape and Tab for cancellation/navigation, and shows application rejection inline without changing displayed entries. Provide full accessible names for icon and removal buttons and written modifier labels for shortcut values.

## Sequence and verification

First implement the application value, command, validation, and schema migration with temporary-directory tests. Then extend adapter and bridge projections and live rebinding. Finally build the Settings pages, help overlays, and capture control. Cover migration, zero/multiple entries, ordering, combinations, cross-scope conflicts, reserved supersets, per-row defaults, stale or failed storage, and capture suppression in focused tests. Native macOS checks cover key display across keyboard layouts, focus and accessibility, live dispatch, Settings/Notices synchronization, reset, and relaunch persistence. Run the repository gate before claiming the milestone complete.
