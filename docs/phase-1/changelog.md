## Entries

- 2026-09-30 — User — Confirmed P1-M4's manual launch: `make run` opens the `Dual Pane` window immediately, the status line shows loading and then the launch directory, the pane shows 100,000 rows with folders first, scrolling stays smooth, and closing the window returns the process normally. - 2026-09-30 — Codex — Post-review corrections: accepted reads now deliver exactly one typed terminal lifecycle event, including when supervisor dispatch is unavailable; source panics, failed worker creation, and disconnected workers are contained and recovered through a bounded-backoff supervisor; formatted status wording moved to the presenter; a C++ queued-event scheduler replaced `CxxQtThread::queue` requeueing; and desktop launch preconditions are guarded. `make check`, direct Rust formatter/Clippy, C++ lint, and `cargo test` passed.
- 2026-09-30 — Claude — Implemented P1-M4 except the manual launch evidence. The CXX-Qt bridge with a `QObject` does generate the `run_desktop` wrapper; the link failure seen in P1-M2 came from version skew: `cxx = 1.0.176` against the locked transitive `cxx-gen 0.7.202`, and cxx embeds its patch version in bridge symbol names. No `extern "C"` fallback ships. `PaneSession` runs its work through a narrow `WorkRunner` trait that `Runtime` implements, so the bounded-drain tests use a deterministic fake. The Qt model shows a copy of the view model that changes only between `beginResetModel` and `endResetModel`. `scripts/lint-cpp.sh` now builds the desktop crate and adds its CXX-Qt generated header directory, located from Cargo's build-script output, so clang-tidy can check the shim.
- 2026-09-30 — User — Approved bumping `dual-pane-desktop`'s `cxx` pin from `=1.0.176` to `=1.0.202` (MIT OR Apache-2.0) to match the `cxx-gen 0.7.202` that CXX-Qt's code generator uses. The bump moves `cxxbridge-macro` and `cxxbridge-flags` to 1.0.202, adds the transitive `cxx-build 1.0.202` and `scratch 1.0.9` (both MIT OR Apache-2.0), and drops `codespan-reporting`.
- 2026-09-30 — User — Decided P1-M4: the list model is a Rust CXX-Qt `QObject` subclassing `QAbstractListModel`, and the worker wakes the GUI thread with `CxxQtThread::queue`; approved moving `cxx-qt-lib = 0.10.0` to a normal dependency of `dual-pane-desktop`; the app shows a 100,000-row synthetic listing, which the next milestone replaces with the real reader; the pane starts at the launch working directory; approved `tempfile` as a `dual-pane-desktop` dev-dependency, to be added with the first directory-reader test. Asked that P1-M4 leave no dead code or stray files.
- 2026-09-30 — User — Accepted three code-review fixes to P1-M3 and approved `unicode-normalization = 0.1.25` (MIT OR Apache-2.0) for the domain crate. Listing results now carry only their token, and the workspace uses the pending navigation's location, so a differently spelled location can no longer leave a pane loading forever. Navigating to the location already being loaded keeps the pending read. Sorting uses a key computed once per entry, and names that differ only in Unicode composition sort together. This supersedes the earlier location check on `ListingLoaded`.
- 2026-09-30 — Claude — Implemented P1-M3. `Event::ListingLoaded` is accepted only when both its token and its location match the pending navigation, and `Workspace` exposes read-only `location()`, `entries()`, and `loading_location()` accessors; [milestone-03-architecture.md](milestone-03-architecture.md) records both. `make check` passed.
- 2026-09-30 — User — Decided P1-M3 behaviors: a failed navigation keeps the previous directory and reports the error; listings put folders (including links to folders) first, then sort in case-insensitive natural order; entry names are exact bytes, with lossy text used only for display and sorting; going to the parent is logical after entering a symbolic link. Approved `proptest = 1.11.0` (MIT OR Apache-2.0) as an inner-crate dev-dependency.
