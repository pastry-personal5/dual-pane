# Phase 1 changelog

Status: Active

Chronological record of decisions, owner calls, and design changes made during Phase 1. Newest entry first.

## Entries

- 2026-09-30 — User — Accepted three code-review fixes to P1-M3 and approved `unicode-normalization = 0.1.25` (MIT OR Apache-2.0) for the domain crate. Listing results now carry only their token, and the workspace uses the pending navigation's location, so a differently spelled location can no longer leave a pane loading forever. Navigating to the location already being loaded keeps the pending read. Sorting uses a key computed once per entry, and names that differ only in Unicode composition sort together. This supersedes the earlier location check on `ListingLoaded`.
- 2026-09-30 — Claude — Implemented P1-M3. `Event::ListingLoaded` is accepted only when both its token and its location match the pending navigation, and `Workspace` exposes read-only `location()`, `entries()`, and `loading_location()` accessors; [milestone-03-architecture.md](milestone-03-architecture.md) records both. `make check` passed.
- 2026-09-30 — User — Decided P1-M3 behaviors: a failed navigation keeps the previous directory and reports the error; listings put folders (including links to folders) first, then sort in case-insensitive natural order; entry names are exact bytes, with lossy text used only for display and sorting; going to the parent is logical after entering a symbolic link. Approved `proptest = 1.11.0` (MIT OR Apache-2.0) as an inner-crate dev-dependency.
- 2026-09-30 — User — Chose the Qt-free domain, application, and adapter crates as P1-M3, ahead of the Qt item-model work. Planned in [milestone-03-overview.md](milestone-03-overview.md) and [milestone-03-architecture.md](milestone-03-architecture.md).
- 2026-09-30 — User — Set the Phase 1 goal to one pane that lists a directory's folders and files and changes directory, with matching exit criteria in [phase.md](phase.md). Added code conventions to [AGENTS.md](../../AGENTS.md): no phase words in source-code names and no `MVP` wording in source code or scripts.
- 2026-09-29 — User — Confirmed that the empty native `Dual Pane` window launched by `make run` closes normally and returns the process. P1-M2 is complete.
- 2026-09-29 — Codex — Installed Homebrew LLVM 23.1.2. `make check` and the equivalent direct formatter, Clippy, clang-tidy, and test commands pass with Qt 6.11.2. The `make run` process remains in Qt's event loop, but this remote session's desktop capture does not expose its raw Qt window, so P1-M2's manual visible-window/normal-close evidence remains pending.
- 2026-09-29 — Codex — Kept `CxxQtBuilder` as the Cargo-only C++/Qt integration and registered the private bridge source, but used the shim's private C ABI for the one no-argument call into Widgets. CXX-Qt 0.10 does not generate a callable wrapper for a bridge containing only an `extern "C++"` function; creating a RustQt `QObject` to satisfy it would violate P1-M2's explicit no-`QObject` scope. `cxx-qt-lib` remains an approved direct dev dependency, ready for the first desktop test that needs a Qt type, without unnecessarily linking its unused C++ bridge code into the binary.
