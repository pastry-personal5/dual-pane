# Phase 1 changelog

Status: Active

Chronological record of decisions, owner calls, and design changes made during Phase 1. Newest entry first.

## Entries

- 2026-09-30 — Codex — Implemented P1-M5 and completed Phase 1. The desktop now reads and sorts real directories on the supervised worker, maps native errors, preserves exact entry identities, owns single selection in the application, and exposes pointer-only folder/link navigation plus logical Up through the Qt boundary. The Qt pane has centralized dark, hover, selection, and Up-hover styling; failures keep the last listing and selection visible. Disposable-hierarchy GUI acceptance covered real rows, hover and selection, empty/right/middle clicks, consumed keys, file/folder/link activation, logical Up, an unreadable child, error recovery, responsiveness, and normal close; modifier semantics are additionally fixed by the view's unconditional `NoUpdate` selection command and application no-op for reselecting the same exact row/name. Acceptance also found that `QThread::isMainThread()` rejected a valid pre-`QApplication` launch, so the macOS-only entry point now uses `pthread_main_np()` while retaining its one-application and one-run guards. `make check` and the direct rustfmt, Clippy, C++ lint, and test commands passed; the exact approved `tempfile = "=3.27.0"` dependency and all newly locked transitive packages have Apache-2.0-compatible licenses.
- 2026-09-30 — User — Finalized the P1-M5 owner decisions and made its plan documents active while leaving the milestone planned. Unclassifiable symbolic-link targets remain visible as non-enterable links; selection and activation use O(1) row/name validation with explicit selection outputs; the Qt boundary accepts only valid-row left-button gestures; P1-M5 is pointer-only, with every list key press consumed and no shortcut or keyboard focus on Up; and implementation will pin `tempfile = "=3.27.0"` with default features in workspace dependencies and enable it only as the desktop crate's dev-dependency. The plan also incorporates the review corrections recorded in the preceding entry.
- 2026-09-30 — Codex — Reviewed the P1-M5 proposal against the implemented P1-M4 boundaries and current Qt/Rust API behavior. Corrected the plan so dangling-link target failures are distinct from an entry's own disappearance, selection clearing is an explicit application output rather than presenter policy, row-originated selection/activation validates row plus exact name in O(1) without GUI-thread listing scans, and a view-specific pointer boundary gates left-button gestures while preventing Qt modifiers, empty-space clicks, other buttons, and built-in list keys from desynchronizing application-owned selection. Recorded the remaining owner decisions for unclassifiable link targets, focused-button activation, and the exact `tempfile` requirement.
- 2026-09-30 — Codex — Reviewed P1-M4 against the architecture's panic, crash, queue, and recovery rules. Replaced the reused mutex-protected listing source with a source factory that constructs fresh job-local state inside each worker's panic boundary; workers now reduce panics to a payload-free marker, and a process hook logs a fixed diagnostic without formatting the payload. Tests cover source-construction and execution panics, a panic-payload destructor that disconnects its worker, no replay, FIFO queue survival, cancellation during backoff, and the 100 ms exponential delay's 5 s cap and reset after recovery. Documented that finite admission, typed saturation, and lane circuits belong to the explicitly post-P1-M4 execution model. `make check` and all required direct commands passed.
- 2026-09-30 — Codex — Reviewed P1-M4 against the architecture's GUI-thread and responsiveness rules. GUI result draining now has both a 32-event limit and a provisional 4 ms elapsed-time budget; fetched results remain buffered across queued Qt turns without losing a concurrent worker wake. Immediate cancellation and unavailable-supervisor events return directly to the GUI-owned pane session, so only the supervisor uses the cross-thread wake path. Restored runtime acceptance coverage for worker affinity, FIFO delivery, bounded slices, wake coalescing, queued cancellation, and shutdown cancellation. `make check` and all required direct commands passed.
- 2026-09-30 — Codex — Post-review correction: made the C++ queued-drain scheduler's cross-thread coalescing flag atomic. Worker wakes and GUI-thread drain callbacks can now safely coordinate without a data race. `make check` passed.
