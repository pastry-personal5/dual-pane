# P3-M15 architecture: File and folder visibility

Status: Active

P3-M15 keeps visibility choices in the Qt-free application, captures them with each directory read, and evaluates them on the listing worker. The Qt Settings page renders three application-owned values; it does not filter rows or persist settings itself.

## Settings and presentation

Add a small typed `VisibilityPolicy` with `show_macos_items = false`, `show_dotfiles = true`, and `show_macos_invisible = false` compiled defaults. Keep it in `SettingsState` and `SettingsSnapshot`, expose three typed commands, and reject changes while settings are not loaded or Settings interaction is unavailable. A changed value increments the existing settings revision once and requests the ordinary coalesced settings save; unchanged input neither rereads nor saves. Compare old and new policies by allowed classes: a transition that turns any Show switch off may hide rows, while one that only turns switches on can only reveal rows.

The SQLite settings driver adds one schema migration and stores all three values in the existing settings database. The migration transaction writes the approved defaults for each absent value, without resetting other settings, Favorites, or the workspace session; an existing profile then keeps that baseline if future fresh-profile defaults change. Invalid stored values are a typed settings-load failure, not a guessed Boolean. Existing explicit Reset Settings seeds defaults and retains its backup and workspace-reset contract. A failed save leaves the effective in-memory policy for this launch, closes Settings, and reports through Notices as it does for other settings.

Project the values through `WorkspaceChrome`, `WorkspacePresenter`, and `WorkspaceBridge` to P3-M14's General page. Each labeled checkbox sends its corresponding command. Help text states that an item matching both a macOS named rule and the dotfile rule appears only when both switches show it. The page reports no local persistence or matching authority.

## Read lifecycle and bounded delivery

Extend `WorkRequest::ReadDirectory`, the runtime `Job`, and `FolderItemsSource` with a copy of `VisibilityPolicy`. `Workspace::start_read` captures it alongside sort and request token. The application keeps a separate visibility generation that advances only when the effective policy changes, including a late settings load; each pending read records that generation. Other settings edits do not invalidate directory reads. The worker neither reads mutable settings nor changes the policy of an already admitted job. A native event returns entries under the captured policy; the application accepts them only for the matching current token and visibility generation.

On any actual policy change, enumerate every open tab's current requested location, including inactive tabs and pending navigation targets. Cancel or invalidate prior reads and preserve each pending navigation's history target. For a change that may hide rows, clear the tab's displayed and actionable Folder Items, selection, cursor, and Quick Look eligibility immediately; retain their identities and scroll anchor only as private reconciliation hints. Clear an inactive tab's cached rows too, so switching tabs cannot resurrect them. Send a full row reset through the existing output/view-model boundary, and read with `previous: None`; do not diff against a broader listing. Retain the tab path, history, and watch interest; project the requested path even while the row cache is empty so a tab switch does not blank its location. A failed read stays empty with the existing listing error and manual Refresh, even when an ordinary watcher refresh would have kept its last successful rows. For a reveal-only change, existing rows remain valid and can stay visible under the ordinary refresh presentation until the new listing succeeds or fails. A late successful settings load after the startup timeout compares its policy to the defaults already in use and, if changed, refreshes the visible Home tabs without restoring the saved tabs or enabling session writes.

The domain allows at most eight tabs per Browser, while each Browser's current read lane admits 16 queued plus its running workers. Rapid toggles can still leave cancelled jobs awaiting terminal delivery, so do not rely on the tab limit alone. Keep at most one desired replacement per tab at the newest visibility generation, prioritize the two active tabs, then use stable tab-strip order for the rest. Treat `Busy` as an admission failure rather than evidence that the folder is inaccessible: retain the desired read, retry it on a later bounded timer or capacity notification, and never resubmit it synchronously from the same terminal-event loop. Preserve a visible loading/error cue and `Command+R` while waiting. A newer navigation, sort, policy change, or tab close supersedes the desired read. Watch invalidations during a visibility reread coalesce into at most one subsequent reread under the latest policy. Distinguish a classification or I/O failure from `Busy`; the former reports an error and waits for manual Refresh or a later invalidation instead of retrying in a tight loop.

## Worker classification

Retain `is_launch_temporary` as the first unconditional check. After `DirEntry::file_type` supplies the entry's own kind, apply the exact-name/type predicate to raw filename bytes. Only regular files match `.DS_Store`, `Icon\r`, `.localized`, and `._*`; only a directory matches `.AppleDouble`; links with those names remain ordinary links unless the dotfile or native-invisible rule applies. The five approved service folder names require proof that the directory being read is that volume's root, including when the root is reached through an alias. Use worker-side native mount identity, not a `/Volumes` string rule. Check it only when a candidate service directory is present and the macOS-items switch is off. If identity cannot be established, return a typed listing failure rather than guess the candidate's placement. Do not follow an item's symlink to classify its target.

For entries surviving the name checks, obtain the item's own macOS invisibility metadata only when that switch is off. The native classifier reads `UF_HIDDEN` and the big-endian Finder `kIsInvisible` bit from the entry's `com.apple.FinderInfo` extended attribute with `XATTR_NOFOLLOW`. `NSURLIsHiddenKey` remains a probe comparator only: its broad “normally hidden” answer must not make every plain dotfile invisible under the third switch. The helper accepts filesystem bytes and runs only on a listing worker through the existing desktop native boundary. Do not rely on lossy `QString` conversion or `QDir::Hidden` for this independent setting. A missing Finder-information attribute means no Finder flag; any other required status lookup failure returns a typed listing failure rather than assuming the item is visible. Disappeared entries keep the reader's existing missing-entry handling. No native status lookup is needed for a row already excluded by a name rule or when the third switch is on.

The [disposable native probe](../../../research/hidden-files-research.md#native-verification-on-2026-10-12) confirms that `NSURLIsHiddenKey` also marks a plain dotfile hidden on the tested APFS volume and that a link does not inherit its target's marker. That volume rejected an invalid UTF-8 filename at creation, so its native UI behavior remains unverified there; byte-exact worker matching is covered by a separate unit test. On the tested volume Finder's invisible bit also surfaced as `UF_HIDDEN`, while the independent Finder-information parser test covers its byte order and bit position.

Give failed mount-root or item-invisibility classification a distinct retryable `ListingErrorKind`, with a useful Status Bar message. A failure about a child entry does not prove the requested folder is missing or unreadable. `Workspace::failed` must keep a restored tab on this error and offer Refresh; do not map it to the existing `Unknown`, `PermissionDenied`, or `PrivacyRestricted` reasons that can discard a tab during restoration. Keep actual failure to open or enumerate the requested folder under the existing restoration rules.

The final decision is the union of applicable hide rules:

```text
hide = current_launch_temporary
    OR (macos_named_item AND NOT show_macos_items)
    OR (name_starts_with_period AND NOT show_dotfiles)
    OR (own_macos_invisible_status AND NOT show_macos_invisible)
```

Skip a hidden entry before `Entry` construction, package recognition, sorting, row diff, icons, or Quick Look requests. Keep byte-exact names through the predicate. The named metadata matcher uses the kinds in the [owner decision table](milestone-15-overview.md#owner-decisions); the dotfile and native-invisible rules also apply to other entry kinds.

## File operations and verification

Do not pass `VisibilityPolicy` to recursive scans or the native executor. Existing operations plan from selected visible roots and scan all descendants on disk. While a stricter-policy listing is empty or failed, there is no selectable source row; command availability must derive from the same current rows as the view, not retained reconciliation hints. Destination existence checks remain independent of the listing, so an omitted item still causes a conflict or name rejection. Explicit path navigation and Favorites likewise do not consult the policy.

Build in this order: verify native invisibility with temporary fixtures and separately validate mount-root detection on disposable test locations; record supported metadata sources and any limitation before choosing the native helper; add values, migration, and Qt-free tests; extend requests and runtime source; apply worker classification; implement all-tab policy transitions and bounded admission retry; then wire General controls and check native interaction. Inject root identity for unit tests; do not create or change macOS service folders on a real volume. Verify that a failed stricter-policy read remains empty while an ordinary failed watch refresh still retains its last successful rows. The full repository gate and native checks complete the milestone.
