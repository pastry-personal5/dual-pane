# P3-M16: GUI polish and Preview Pane

Status: Done

P3-M16 refines the Favorites controls and gives each Browser a compact, expandable Preview Pane above an always-visible, one-line Browser Status Bar. The Preview Pane starts at zero content height, measured separately from its splitter handle, and expands into item content and details for the current selection without moving file I/O or image decoding onto the GUI thread.

## Scope and owner decisions

Use the existing [Visual layout and accessibility](../../../ux-gui.md#visual-layout-and-accessibility), [Sidebar Favorites](../../../ux-gui.md#sidebar-favorites), [Folder Items fields and display](../../../ux-gui.md#folder-items-fields-and-display), [P3-M9 session layout contract](milestone-09-architecture.md#layout-capture-and-restoration), and [P3-M12 visual rules](milestone-12-architecture.md). P3-M14, P3-M15, and P3-M16 are complete.

| Topic | Approved behavior |
|---|---|
| Favorite controls | Favorite Group Menu (three-dot) and Add Favorite Item (plus) buttons use `#A7ADB5` on `#24282E` normally, white on `#2F6D9A` on hover, white on `#245878` while pressed, `#6F757D` on transparent while disabled, and `#8A9099` on `#1B1D21` in an inactive Sidebar. Their button state remains visually distinct from the parent Favorite Group row and does not alter the existing actions, accessibility names, or pointer routing. |
| Preview placement | Each Browser places a Preview Pane below its Folder Items area, separated by its own draggable, vertically oriented splitter. The Browser Status Bar stays at the Browser's bottom, below the Preview Pane and outside that splitter. The splitter handle remains visible when the Preview Pane's content height is zero. |
| Browser Status Bar | The Status Bar remains exactly one readable text line high at every Preview Pane height. It retains the current steady-state and transient text and precedence, including blank-before-first-listing, loading, errors, monitoring, command feedback, startup reader failure, and Quick Look failure. Long text elides on screen without increasing height and remains available to accessibility. |
| Collapsed and expanded layout | The Preview Pane's default and minimum content height is zero, excluding the separate splitter handle and Status Bar. Expanding it reveals Item Content Preview at about two thirds of the usable width and Item Details Preview at about one third. Releasing the splitter between zero and the minimum useful content height snaps it to that useful height; a drag back to zero hides preview content while the Status Bar remains visible. |
| Selected image | With exactly one selected regular image file and an expanded Preview Pane, Item Content Preview shows that image fitted within its available area without upscaling. Item Details Preview includes image width and height in pixels and byte size, plus normal available Item identity and metadata. |
| Image formats | The built-in Preview Pane supports formats the installed Qt image reader can decode. Detection uses file content rather than the displayed filename extension; the app does not promise support for a format absent from that Qt installation. |
| Other selections | The milestone does not add generic document, video, audio, directory, package, link, or multi-selection content renderers. The expanded pane reports a concise unavailable or multiple-selection state in Item Details Preview; it never presents a stale image from a former selection. |
| Lifetime and persistence | Preview requests are per Browser active tab and are invalidated on selection, tab, location, listing, preview-target-size, or collapse-to-zero changes. A decoded result is accepted only for the current request identity. Each Browser saves its chosen Preview Pane content height in logical points, excluding the splitter handle and Status Bar, and retains it when the window resizes; a temporarily constrained window does not overwrite the chosen height. Zero is an explicit stored value. |

In scope: the two Favorites button color treatments; per-Browser Preview Pane composition and accessibility; preservation of the one-line Browser Status Bar; per-Browser vertically oriented splitter interaction and durable layout; selection-driven image preview and details; background image metadata/decode work with bounded delivery and stale-result rejection; focused temporary-file tests; native macOS visual and accessibility checks; and directly affected UX, architecture, README, and acceptance evidence updates.

Out of scope: a general built-in file viewer; text, media, PDF, folder, package, link, or multiple-item previews; changing Quick Look; a new user preference; changing file-manager selection, navigation, or operation behavior; changing Favorites data or command handling; a new third-party dependency or build tool; and reading, decoding, or scaling files on the GUI thread.

## Completion checklist

- [x] The shared desktop styling gives the Favorite Group Menu Button and Add Favorite Item Button their approved foreground and background colors for ordinary, hover, pressed, disabled, and inactive-Sidebar states. Their parent row hover remains suppressed while either button owns the pointer, and existing actions, keyboard access, tooltips, accessible names, and resize behavior remain intact.
- [x] Every Browser keeps its Browser Status Bar at the bottom, below the Preview Pane and outside the vertical splitter. It is exactly one font-measured, readable text line high at zero and expanded preview heights, including when blank; long text elides without wrapping and remains available to accessibility. Blank-before-first-listing, concise summary, loading, error, monitoring, startup-reader-failure, command-feedback, and Quick Look-failure precedence is preserved and visible at every preview height.
- [x] The Preview Pane has named, keyboard-accessible Item Content Preview and Item Details Preview children. Its content height defaults to zero and can return to zero without hiding the splitter handle or Status Bar. Expanded content and details divide usable width about 2:1; a release between zero and usable expanded height snaps to the latter. The Folder Pane keeps its controls and at least one usable list row, and expansion does not overlap the Missing Folder Overlay, tabs, path, Status Bar, or Operation Panel Strip at usable widths. Below the existing narrow-Browser threshold, the Expand overlay retains its current precedence.
- [x] Each Browser's Preview Pane splitter supports pointer and Full Keyboard Access interaction, restores a validated saved content height after the workspace is laid out, and writes a coalesced session update after settled user movement. Stored and measured content height excludes the splitter handle and Status Bar. A window resize retains each chosen logical-point height, including after a temporary space constraint. Fresh, legacy, corrupt, and out-of-range Preview Pane heights use zero without discarding otherwise valid saved tabs or window geometry.
- [x] Expanding a Preview Pane evaluates only its Browser's active tab selection. A single selected regular image starts a cancellable, bounded background request using the exact native path; no display-path conversion can select a different file. Collapse to zero, selected-item or listing-generation change, navigation, tab switch or close, file-operation refresh, preview-target-size change, and teardown invalidate obsolete work. Cursor-only movement that leaves selection unchanged does not request another preview.
- [x] The background image reader detects formats supported by the installed Qt image reader from file data, obtains dimensions and byte size, decodes a preview scaled for the current content area, and returns a typed unsupported, unavailable, or failure result. It neither blocks the GUI thread nor follows a link merely to render its target. Saturated admission retains only the latest pending request per Browser and retries when capacity returns. Results are accepted only when their Browser, tab, selected entry identity, listing generation, requested size, and pane request token still match.
- [x] With an expanded Preview Pane and exactly one selected supported image, Item Content Preview shows a correctly oriented, aspect-ratio-preserving image without upscaling. Item Details Preview identifies the Item and shows its width × height and formatted byte size; unsupported, unreadable, disappeared, non-image, and multiple selections replace both the content and details appropriately and cannot leave stale pixels or dimensions.
- [x] Human acceptance: the owner reported success on 2026-10-12.
- [x] Affected product/UX/README documentation is updated. Formatting, Rust lint, C++ lint, workspace compilation, and diff checks pass.
