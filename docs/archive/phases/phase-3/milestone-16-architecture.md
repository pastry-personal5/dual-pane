# P3-M16 architecture: GUI polish and Preview Pane

Status: Active

P3-M16 keeps state ownership and presentation boundaries intact. Qt owns Preview Pane geometry, widget lifetime, and painting; the application owns request identity and stale-result acceptance; the desktop runtime performs file reads, image metadata lookup, scaling, and decoding on a bounded worker lane.

## Desktop composition and visual states

Keep the existing Browser Status Bar `QLabel` and its status projection, but move it out of `FolderPane` into `Browser` below a new vertical `QSplitter`. The splitter sits below the Browser tabs and path, with the existing `FolderPane` above a private `PreviewPane`; the Status Bar remains at the Browser's bottom, outside the splitter. Extend the existing thin splitter treatment to vertical orientation with a dedicated accessible name and keyboard-operable handle; do not put a layout on the splitter itself. Configure the Folder Pane child as noncollapsible and the Preview Pane child as collapsible, overriding any global noncollapsible setting inherited from the existing thin splitter. Ensure `PreviewPane` and its child layout permit zero minimum height. Keep both child widgets in the splitter when Preview Pane content height reaches zero; do not call `hide()` on the Preview Pane widget, which would remove it from splitter sizing. Its three-pixel splitter handle stays visible and is measured separately. The Browser's minimum height reserves its tabs, path, Folder Pane controls, one usable Folder Items row, splitter handle, and Status Bar.

Fix the Status Bar's height to one readable line measured from its current font plus vertical insets, including when its text is blank or the Preview Pane is expanded. Long text elides without wrapping, while the full text remains available to accessibility. Preserve its existing precedence: temporary Quick Look failure, loading/error/monitoring/command status, then concise summary, otherwise blank. Reroute the existing startup-reader-failure update to the moved label. The Status Bar remains visible and continues updating at every Preview Pane height.

At zero Preview Pane content height, suppress its child content while retaining the vertical splitter handle. On expansion, show a horizontal child splitter with Item Content Preview and Item Details Preview. Derive a minimum useful expanded content height from font metrics and a design minimum that fits at least one metadata row and a nonzero image viewport; never derive it from an image's native dimensions. If a drag or keyboard movement ends between zero and the useful height, snap to the useful height; moving back to zero invalidates preview work. Establish a 2:1 initial content/details ratio and retain it through Browser resizing. Keep the child minimum widths below the existing narrow-Browser threshold so the horizontal splitter cannot prevent the Browser Divider from moving. The existing Expand overlay still covers the Browser below that threshold. The image widget preserves aspect ratio, centers the image, and never scales above the decoded image's native dimensions. The details child uses selectable, accessible text; its fields include Item name, Type, Modified, Size, and, for an image, Dimensions. No selection, multiple selection, unsupported content, and read/decode failure each have an explicit details state and no retained image or dimensions. Do not create a Qt layout on either splitter.

Extend the stylesheet with explicit Favorite Group Menu and Add Favorite Item foreground/background state selectors. The colors must cover normal, hover, pressed, disabled, and an inactive Sidebar. Button hover suppresses the parent `FavoriteGroupRow` hover; selection, focus, inline-edit, disabled, and error priorities continue to follow P3-M12.

## Preview request boundary

Add an application-owned preview request/result pair to the existing input, output, and work-request boundary. A request copies Browser side, active tab ID, current listing generation, selected `EntryName`, exact byte native path, requested image target size, and a monotonically increasing preview token. The Browser starts one only when its Preview Pane has positive, usable content height and its current active tab has exactly one selected `EntryKind::File`. A cursor-only movement does not change the selected target or start new work; the existing presenter `selection_revision` also advances on cursor changes, so it is not the sole preview identity. Selection itself still belongs wholly to the existing Folder Items workflow.

The desktop runtime receives preview work independently of directory reads and file operations. It has bounded admission and cooperative cancellation, coalesces pending replacement requests by Browser, and reserves one terminal delivery per admitted job. If admission is saturated, retain only the newest pending request per Browser and retry when capacity returns; neither discard the current request silently nor build an unbounded queue. A worker opens the exact native path as a regular file without following a link, then reads through the installed Qt `QImageReader` with `setDecideFormatFromContent(true)`, so the data stream rather than a filename extension selects the installed reader. It checks format and source dimensions before decoding, enforces source-byte, decoded-pixel, and delivered-payload bounds, applies orientation, and decodes at a size no larger than the current content target. The details report dimensions in the displayed orientation. The worker obtains byte size from the opened file's own metadata, so a changed or disappeared target becomes unavailable instead of borrowing stale listing metadata. It returns a typed supported preview, unsupported format, unavailable file, decode failure, or cancelled result. A worker never touches `QWidget`, a list model, workspace state, or a shared image widget.

The application accepts a result only if the Browser still shows the captured tab and listing generation, exactly the captured single selected `EntryName`, the Preview Pane still has usable positive content height, the requested target size matches, and the token is current. Any selection change, listing replacement, navigation, tab activation/close, collapse to zero, Browser teardown, or newer target size invalidates the token before cancellation is requested. The presenter maps accepted state to plain preview content/details view data; the CXX-Qt bridge carries copied image data or a desktop-owned immutable image payload only after the match. The UI clears image and dimensions immediately on invalidation, which prevents cross-tab, cross-Browser, and stale-result display. Browser status feedback remains in the separate Status Bar at every preview height.

The domain `Entry` remains a listing record. It does not acquire image dimensions or decode fields, because those data are demanded only for an expanded single-item preview and are neither directory-sorting data nor enduring workspace state.

## Layout persistence

Extend the existing `WindowLayout`, session snapshot, SQLite `session_window` row, bridge properties, and `updateWindowLayout` call with `left_preview_height` and `right_preview_height`. Each field stores the person's chosen Preview Pane content height in logical points, measured from the Preview Pane widget only: the three-pixel splitter handle and one-line Browser Status Bar are excluded. Zero means a fully collapsed Preview Pane with its handle still visible; a positive value is the chosen expanded content height. A transactional schema migration adds both fields with zero defaults for older sessions. Accept stored heights only from zero through 32,767 logical points; decode a missing, malformed, negative, or larger value as zero independently for each Browser. A bad preview field alone must not discard otherwise valid tabs, frame, window state, or existing splitter positions. A valid saved height that exceeds the current usable window height remains the chosen height; only its effective on-screen height is constrained.

On restoration, show and lay out the window, then apply Sidebar, Browser Divider, and per-Browser Preview heights on the next queued GUI turn. Keep the chosen positive content height when the window is resized; the Folder Pane takes or gives the difference. A valid positive height below the current useful expansion threshold displays at that threshold. If space is temporarily insufficient to show a usable expanded pane, show zero effective preview content height while preserving the chosen value for later growth and persistence. Report the chosen value, not the temporary effective size, during ordinary window resize and close reporting. Only a settled person-initiated Preview splitter movement replaces that chosen value, with zero when collapsed. Debounce it through the existing layout-report and session-save path. Reset Settings clears both heights to zero with the rest of the layout.

## Delivery order and verification

1. Update UX containment/rules and P3-M16 plan decisions, then add layout fields with migration and Qt-free validation tests, including recovery from an invalid preview value while other saved layout data stays valid.
2. Refactor the Browser composition around `PreviewPane`, keep the one-line Browser Status Bar below the splitter, enforce zero preview content height with a visible handle and a useful expansion snap, and add dedicated splitter state restoration/reporting.
3. Add Favorite button state styling and desktop object/property seams.
4. Add application preview identity, reducer transitions, and presenter view data with focused stale-result tests.
5. Add the bounded desktop image reader and CXX-Qt bridge, using temporary files for supported image, corrupted data, disappearance, and byte-exact-path checks.
6. Wire the expanded view, resize replacement requests, clearing behavior, and details text; run native macOS checks after the full automated gate.

No new third-party dependency or build tool is required. [Qt's `QSplitter` documentation](https://doc.qt.io/qt-6.11/qsplitter.html) supports per-child collapse to zero; explicit Preview Pane code supplies the visible handle, expansion snap, and fixed-height resize behavior. [Qt's `QImageReader` documentation](https://doc.qt.io/qt-6.11/qimagereader.html) defines installed format support, content-only detection, automatic transformation, and scaled decoding through the existing dynamically linked Qt installation.
