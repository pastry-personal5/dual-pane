# UX GUI

Status: Active

This document defines the current interface, delivered Phase 3 GUI behavior, and accepted Phase 4 interaction decisions for planned features. Product scope is in [product-behavior.md](product-behavior.md); component vocabulary is in [ux-terms.md](ux-terms.md).

## Visual layout and accessibility

The main application window has no native title bar. The main Sidebar begins with a prominent **Dual Pane** title row; dragging this row moves the window through the platform window manager. The Browser Tabs Strip is reserved for tab interaction: tab buttons activate and reorder tabs, and the New Tab Button creates a tab.

Both Browser layouts have zero outer margins and zero gaps between child components for a flat, edge-to-edge appearance. Folder Pane borders and splitters use `#3A4048`; a key-window active Folder Pane uses a one-pixel `#2F6D9A` border. Active selected rows use `#2F6D9A` with white text; inactive-Browser selected rows use `#173A55` with white text. When the application window is inactive, neither Folder Pane has an accent border and both selections use `#173A55` with white text. An inactive Browser uses `#17191D` surfaces and `#8A9099` non-selected text, visibly dimmer than the active Browser’s `#23262B` surface and `#ECEFF3` text; selection, error, and focus feedback remain legible. Keyboard focus retains a clear `#2F6D9A` indicator rather than dimming into the inactive surface. Back, Forward, and Up use blue-accent hover feedback; sort controls use restrained neutral-gray hover feedback. The Up Button and the eight sort buttons in Folder Pane Toolbar Row #3 have no border.

The Sidebar Splitter, Browser Divider, and each Preview Pane Splitter are three-pixel draggable strips. Hovering adds a gray border; primary-button dragging removes that border until release. The current accessible names include Sidebar Splitter, Browser Divider, Preview Pane Splitter, Browser Tabs Strip, Settings, Path Edit Control, Up Button, Folder Items List, Item Content Preview, and Item Details Preview. The Settings Window also provides accessible names for its Close button, categories, help controls, and shortcut actions. Controls retain these names as the window resizes; both Browsers share available space through their splitters without overlapping or suppressing ordinary interaction. Enabled Main Toolbar Settings and Notices Button controls use `#2F6D9A` blue-accent hover feedback. The bottom-anchored Main Toolbar Settings control is enabled and focusable only while settings storage is healthy.

## Input and active-Browser state

On macOS, `Control+Command+F` toggles the main Dual Pane window between full screen and its normal window state. This fixed workspace command is not user-editable in Keyboard Shortcuts Settings.

The following table records version 2.0.0 behavior. Mouse and keyboard invoke the same application commands. Both Browsers open at the launch working directory; the Left Browser is active and its Folder Items List has keyboard focus. The active Browser is the target for Browser-specific commands.

| Gesture | Result |
|---|---|
| Primary click in a row | Activate that Browser and select the row. |
| Primary double-click in a row | Activate that Browser, select the row, and activate the row. |
| Primary click in empty Folder Items List space | Activate that Browser and clear selection. |
| Primary click on a Folder Items List scrollbar | Activate that Browser; leave selection unchanged. |
| Primary click on the Up Button | Activate that Browser and navigate to its parent. |
| Modified primary click | Behaves as the corresponding unmodified primary click. |
| Secondary or middle click | No-op. |
| Keyboard focus entering a Folder Items List | Activate that Browser. |
| `Option+F` | Activate the other Browser and move keyboard focus to its Folder Items List, preserving both selections and scroll positions. |
| Plain Tab | Reserved for macOS Full Keyboard Access; no file-manager command. The Up Button is not in keyboard focus traversal. |
| Exact Up, Down, Home, End, Page Up, or Page Down | Select according to the active Browser’s Folder Items List. Boundary movement is a no-op. With no selection, Home, Page Up, Up, and Down select the first row; End and Page Down select the last. Page Up and Page Down move by the number of fully visible rows, clamp at the boundary, and keep the selected row visible. With zero rows, all navigation is a no-op. |
| Exact Left | Navigate the active Browser to its parent; root is a no-op, including when the Folder Items List has zero rows. |
| Exact Right | Activate the selected row; without a selection or when the item cannot be entered, this is a no-op. |
| Exact Return | Activate the selected row, or no-op without selection. |
| Exact Command-Up | Navigate the active Browser to its parent; root is a no-op. |
| `Command+W` / `Command+Q` | Close the current workspace window / quit the app. |
| Modified movement key, modified Return or Command-Up, or any other gesture | No-op. |

## Responsiveness during work

The current implementation runs directory loading on separate Browser workers and keeps the last successful Folder Items visible while a read is pending or fails. A slow or unavailable location affects only the Browser that requested it; a newer navigation request takes precedence over an older result.

Automatic refresh, session persistence, and file operations are committed product scope but were not delivered in the version 2.0.0 release. Automatic refresh is now delivered in the Phase 3 development build; session persistence and file operations are also delivered there. These features must not stall typing, pointer interaction, dialogs, rendering, or accessibility feedback; the implementation constraints are in [architecture.md](architecture.md#51-threading-and-responsiveness).

### Folder Items fields and display

- The columns appear from left to right as Item Icon Column, Name, Type, Relative Date Column, Exact Date Column, and Size. The Item Icon Column shows each Folder Item's macOS native icon, as Finder shows it, and has no sort buttons. The Folder Items List has no column header row; the sort buttons, their tooltips, and accessible names identify the fields. Columns size themselves, Name takes the remaining width, and people cannot resize them. Icons load off the GUI thread, so a row may appear before its icon. The two date columns show the same modification timestamp in different forms.
- The Relative Date Column uses compact elapsed units such as `17 h`, `2 d`, `11 M`, and `2 y`. Its text updates when the folder reloads; no periodic timer updates it.
- The Relative Date Column shows `now` for a timestamp less than one minute old or in the future, and `N min` for less than one hour; larger values use the units above.
- Relative Date text is black on an age-colored background behind that text. Imagine a horizontal color strip from red at position 0 to violet at position 1. An Item aged one hour or less, including a future timestamp, maps to 0; one day maps to 0.25; seven days to 0.50; 30 days to 0.75; and 365 days or more to 1. Between these ages, interpolate the strip position linearly by elapsed seconds and clamp outside the range. In the active Browser, the strip uses HSL hue 10° through 260°, 55% saturation, and 80% lightness, giving `#E8B9B0` at the red end and `#C3B0E8` at the violet end. When the Browser is inactive or the window loses focus, dim the strip to 20% saturation and 60% lightness, giving `#AD8985` and `#9485AD`; the color updates immediately with focus. A missing modification time keeps `—` with black text on neutral light gray, `#D0D0D0` when active and `#888888` when dimmed. The age color uses the same listing-time snapshot as the relative text and changes on reload, not by timer. Selection and focus remain visible around the colored text.
- The Exact Date Column uses a local timestamp such as `2026-09-30 20:21`. Size uses decimal units such as `112.5 KB`, with one decimal place from KB upward and whole bytes below that, such as `512 B`. Unavailable values show `—`.
- Type shows `[DIR]` for a folder and `[LNK]` for any symbolic link, whatever its target. Other Items show the lowercase text after the last `.` in their name, so `.gitignore` shows `gitignore` and `a.tar.gz` shows `gz`; a name without a `.` shows a blank Type. Type sort compares this displayed text.
- Folders show a blank Size cell, not `—`, and are excluded from Folder Pane size totals. Links to folders count as folders. After the first successful listing, Folder Pane Toolbar Row #2 and Browser Status Bar both show a grammatically inflected item count followed by `M selected`: `1 item 1 selected`, but `0 items` and `N items` otherwise. `M selected` uses muted blue text in Row #2. Both remain blank while a location has no successful listing yet, and retain their last-successful values during later loading or failure; temporary loading, error, monitoring, and command feedback continues to take precedence in Browser Status Bar. At the right Row #2 shows `selected size / folder size` when Items are selected, otherwise the folder size; both are non-recursive sums over the included non-folder Items and show `—` when any included size is unknown.

### Preview Pane

- Each Browser has a Preview Pane below Folder Items, separated by its own vertically oriented splitter. Browser Status Bar stays at the Browser's bottom, below the Preview Pane, and remains one readable line high whether the Preview Pane is collapsed or expanded. Its ordinary and transient messages remain visible in both states. Preview surfaces and details follow the active and inactive Browser visual treatment.
- The Preview Pane starts with zero content height, excluding its visible three-pixel splitter handle and Browser Status Bar. Expanding it reveals Item Content Preview on the left at about two thirds of the width and Item Details Preview on the right at about one third. A release just above zero snaps to a useful expanded height. Each Browser retains its chosen Preview Pane content height in logical points as the window resizes and across relaunches. With exactly one selected regular image file, the content pane fits that image without upscaling, while the details pane shows the Item's identity, available metadata, image width and height, and byte size.
- Other selection types and multiple selection have no built-in content renderer in Phase 3; the details pane explains the selection state and no earlier image remains visible. Preview requests follow the active Browser Tab and are cancelled or invalidated when selection, listing, location, tab, or preview size changes.

### Sort controls and remembered choice

- Name, Type, Date, and Size each have separate ascending and descending buttons; there is no direction-toggle cycle. Both Date displays share one Date button pair and sort by the same modification timestamp.
- The eight direct buttons sit beside the Up Button in Folder Pane Toolbar Row #3. They are very small bitmap carets (`^` for ascending and its inverse for descending), with descriptive tooltips and accessible names.
- A field's button pair is shown only while its field is visible. The Date pair remains while either date column is visible.
- Folders, including links to folders, stay ahead of non-folders for every sort. Type, Date, and Size compare their selected field and direction, then use natural Name ascending to break ties in either direction. A folder without a remembered choice starts at natural Name ascending. A chosen sort is shared by location across Browsers and tabs and restored from persistent storage; the [P3-M2 plan](archive/phases/phase-3/milestone-02-architecture.md#folder-sort-memory) owns its retention and storage rules.

### Narrow Browser behavior

- As a Browser narrows, hide columns in this order: Size, Exact Date Column, Relative Date Column, Type, Item Icon Column. Name remains visible while the Browser is usable. Hide each field's sort controls with it.
- Below a 280-pixel Browser width, cover that Browser with a semi-transparent layer and center large, legible `Expand` text both horizontally and vertically. The text is an instruction, not a button; the person drags the Browser Divider to expand the Browser.

### Keyboard Shortcuts Settings (P3-M14)

- The editor lists every [catalogued action](ux-terms.md#canonical-actions) in five human-readable category cards: Navigation, Tabs and Windows, File Actions, Sorting, and Other Actions. Each card has a group heading and repeats the Action, Shortcuts, Original Shortcuts, Scope, and Add headers. There is no outer table card. Fixed columns stay compact around their content. Shortcuts is fixed to the measured width of the longest allowed modifier-and-key label, plus the Remove control and its gap; it does not expand to fill unused space. Each left-aligned card ends just beyond the Add column, with a small right inset.
- Each action occupies one row. Its current shortcuts appear one per line, each with an individual Remove control aligned to the right edge of Shortcuts. Add has a dedicated column, so an action with one current shortcut has no extra Add line. Original Shortcuts always shows the compiled factory default list, with each combination on its own line and “None” when the list is empty. The bitmap Reset to Default Shortcuts control sits beside that list and replaces the action's complete current list with its factory defaults. Move to Trash has `Command+Delete`, Shift+Backspace, and Shift+Delete as defaults.
- The information button sits at the right edge of the Action cell. Its keyboard-accessible popup is anchored to the button, uses a dark slate surface (`#2B323B`), near-white text (`#F4F6F8`), and a visible gray border (`#56616E`); the surrounding popup uses a darker surface and lighter outline. Escape or an outside click dismisses it and returns focus to the button. Add, Remove, and Reset to Default Shortcuts are compact bitmap controls with gray glyphs that turn light blue on hover or keyboard focus. Add enters shortcut capture in place; rejection feedback appears within that action's row area.
- An action may have any number of distinct single-key shortcuts or none. Capture grammar, modifier labels, cross-action conflicts, reserved combinations, and validation feedback follow the [P3-M14 owner decisions](archive/phases/phase-3/milestone-14-overview.md#owner-decisions) and the [P3-M2 action contract](archive/phases/phase-3/milestone-02-architecture.md#actions-and-shortcut-settings). Removing the final shortcut deliberately unbinds the action; resetting the row restores its factory defaults. The fixed `Command+,` shortcut opens Settings and cannot be assigned to another action.

### Settings Window (P3-M14)

#### Settings page grouping principle

Detailed Settings controls are grouped into labeled cards by the task or subject they affect. Each card has a concise heading; add a short description when it helps explain the group. Keep related controls and their help together, and keep independent groups visually distinct. The component hierarchy records card contents; this document records their visual and grouping behavior.

- The Main Toolbar Settings control and fixed `Command+,` open or raise one parented, application-modal Settings Window only while settings storage is healthy. The window has a left Settings Category List with General Settings and Keyboard Shortcuts Settings. Its frameless full-width title row places a small bitmap Close button at the far left, followed by the **Settings** heading, and moves the window when dragged outside the button. It has no footer action; Escape and Close dismiss it. On macOS, parented window-modal dialogs become attached sheets, which cannot move independently; application modality keeps the workspace blocked while allowing a movable Settings window.
- The Settings Window has a 1400 by 900 logical-pixel minimum. Its category sidebar uses the workspace’s dark window surface, blue selected state, neutral hover state, and divider; its content pane uses the Browser surface so the dialog reads as a focused extension of the main workspace. Its draggable title row spans the window and contains the Settings heading and small bitmap Close button. Escape and Close dismiss the window.
- General Settings groups detailed controls into labeled cards: Startup Notices, Item Visibility, and Reset Settings. Item Visibility contains the three macOS metadata/service, dotfile, and macOS-invisible switches plus the overlapping-rules explanation. Reset Settings asks for confirmation before replacing app settings, Favorites, open tabs, and workspace layout with their defaults; the database is retained as a backup.
- Settings opens or raises one parented application-modal window from the Main Toolbar Settings control or fixed `Command+,`. It is available only when settings storage is healthy. A storage failure disables both entry points and dismisses an open Settings Window; Notices keeps its existing recovery path.
- Item-specific help behavior, shortcut categories, row content, keyboard capture, and reset behavior are defined in [Keyboard Shortcuts Settings](#keyboard-shortcuts-settings-p3-m14) and the [P3-M14 owner decisions](archive/phases/phase-3/milestone-14-overview.md#owner-decisions).
- P3-M15 adds three independent General controls: “Show macOS metadata and service items” (off by default), “Show dotfiles” (on by default), and “Show items marked invisible by macOS” (off by default). Help text explains that an Item hidden by more than one rule needs each applicable Show control enabled. A change updates both Browsers and all tabs; while the new listing loads, old rows from a broader policy are not displayed or actionable. The [P3-M15 decision table](archive/phases/phase-3/milestone-15-overview.md#owner-decisions) defines exact matches and persistence.

### Sidebar Favorites

- The Sidebar supports one level of Favorite Groups, each containing ordered Favorite Items. A Favorite Item opens its target in the active Browser Tab.
- Each Favorite Group is a modern borderless `#15171A` container with a 6px radius, surrounded by an 8px Sidebar margin on all four sides. Its Group row, Items, and inline editors have 4px top/bottom and 8px left/right padding, with no inter-row spacing. Favorite Group names use bold 13px text; Favorite Items use regular 13px text to match Browser Folder Items. Hovering an enabled row changes its full-row background to neutral gray `#2B3037` without moving content; selection, inline editing, disabled state, and error feedback take precedence over hover. Favorite Group Menu Button and Add Favorite Item Button use `#A7ADB5` on `#24282E` normally, white on `#2F6D9A` on hover, white on `#245878` while pressed, `#6F757D` on transparent while disabled, and `#8A9099` on `#1B1D21` in an inactive Sidebar. Their hover still does not highlight the parent row.
- Each Favorite Group row shows its name, a borderless Favorite Group Menu Button, and a borderless Add Favorite Item Button. The latter adds the active Browser Tab's current folder to that group and uses the folder's current name as the new Item alias. If that alias already exists in the group, nothing is added and the group row briefly shows “Already in this group” without adding a Notice. The Favorite Group Menu offers rename, move up, move down, move to top, move to bottom, and delete. The New Group Button sits below the list, left-aligned to Group boxes and with matching 8px left text padding.
- A single primary click on a Favorite Item opens its target in the active Browser Tab and moves keyboard focus to that Browser's Folder Items List. Right-click opens the Favorite Item Context Menu without opening the target.
- The New Group Button adds a draft group row with an empty Favorite Group Name Editor; the group exists only after a valid name is committed.
- Favorite Group Name Editor and Favorite Item Alias Editor edit names inline. Return commits valid text; empty, whitespace-only, or duplicate text keeps the editor open and focused with an error. Escape cancels. Focus loss commits valid text and silently cancels invalid or duplicate text, leaving the previous name, or no group for a draft. A Favorite Item's right-click Favorite Item Context Menu offers removal from its group and Change alias; that menu is pointer-only. Dragging a Favorite Item reorders it or moves it between groups; reordering and group movement have no keyboard command. Under macOS Full Keyboard Access, focused Favorite Items use arrow keys to move focus and Return to open their targets. The [Favorites policy](product-behavior.md#favorites) defines exact-text uniqueness, alias meaning, deletion, and launch removal.

### Browser Tabs Strip and navigation

- Keyboard focus entering any control inside a Browser activates that Browser before a Browser-specific command is handled. This includes its Browser Tabs Strip, Folder Pane controls, and Folder Items List; moving focus among controls within one Browser leaves it active. The version 2.0.0 rule above covers only focus entering a Folder Items List.
- `Command+T` or the borderless New Tab Button adds a Browser Tab at the active Browser Tab's current folder and activates it. Each Browser holds at most eight tabs; at that limit the New Tab Button and `Command+T` are disabled, and the button's tooltip says the tab limit was reached. Browser Tabs can be dragged to reorder them; reordering has no keyboard command.
- `Command+W` closes the active Browser's Browser Tab; Close Window has no default shortcut. If another tab remains, activate the nearest one on the right, then the nearest on the left. Closing the last tab replaces it with a clean Home tab at the user's home directory. `Command+Q` quits the application by keyboard.
- Each Browser Tab shows its folder name; the root folder uses its volume name, such as `Macintosh HD`, or `/` when that name cannot be read. A new Favorite Item created at the root uses the same label as its alias. When tabs do not fit, they shrink and elide their labels; the strip does not scroll. Hovering an inactive Browser Tab uses neutral-gray feedback; selection and keyboard focus retain their stronger states. Each tab's full path appears in a tooltip and accessibility text so repeated folder names remain distinguishable. Its borderless Close Tab Button appears only while that exact Browser Tab is hovered.
- Back Button, Forward Button, and Up Button appear in that order at the left of Folder Pane Toolbar Row #3. They use purpose-made monochrome local bitmap icons rather than text glyphs: Back and Forward are arrows with visible shafts, and Up is a matching vertical shafted arrow. Their tooltips and accessible names remain unchanged. Back and Forward follow the active tab's history; after Back, a new navigation discards its Forward history. `Option+Left Arrow` and `Option+Right Arrow` navigate Back and Forward when focus is outside text editing. Up and `Command+Up` navigate to the parent.
- Browser Tab switching retains that tab's selection, cursor, and scroll. Back rereads the folder and restores the matching view state. History belongs to a tab and lasts only for the session.
- The Path Edit Control continues to display the active tab's confirmed folder path. It remains read-only and outside keyboard focus traversal; typing a path does not navigate in Phase 3.
- Under macOS Full Keyboard Access, focused Browser Tabs use arrow keys to move focus and Return to activate the focused tab. Focused buttons use standard Return or Space activation. Plain Tab remains reserved for Full Keyboard Access.

### Selection and file commands

- A plain click replaces the selection and sets the cursor and range anchor to that row. An unmodified movement key that selects a row also establishes a range anchor; after a range selection, the next plain movement key collapses it to one selected Item and sets that row as the anchor. Command-click toggles the clicked Folder Item and moves the cursor there, even when it deselects the row; it moves an existing anchor there but does not establish one when none exists. Shift-click and Shift-arrow extend a range from the fixed anchor while the cursor moves, and are no-ops until a plain click or unmodified movement selects a row and establishes an anchor. `Command+A` selects all visible Folder Items without moving an existing cursor or anchor and does not establish a missing anchor. Right-click on a selected Item keeps the selection; right-click on an unselected Item selects that Item alone without establishing a missing anchor. With no cursor, Up, Down, Home, and Page Up select the first row and End and Page Down select the last. Movement keys start from the cursor even when no Item is selected, so after a Command-click deselects the last selected Item, Down selects the next row. Right and `Command+Down` activate the selected Item only when exactly one Item is selected, even if the cursor is on another row; otherwise they do nothing. A selected folder is entered; a selected file is opened with its default application. Selection, cursor, and anchor belong to the Browser Tab. These planned gestures supersede the version 2.0.0 modified-click and secondary-click rows above once delivered.
- Copy to Other Browser and Move to Other Browser appear in the Folder Items Context Menu and use `Option+C` and `Option+M`. Both require one or more selected Items, a confirmed source folder, and a confirmed, available destination folder in the other Browser's active tab. At command start, capture the source selection and destination folder. Later selection or tab changes do not retarget that job. Disable both commands when source and destination are the same folder.
- Rename Item uses F2, Return, or the Folder Items Context Menu, requires exactly one selected Item, and opens the inline Rename Item Editor. New Folder uses `Shift+Command+N` or the empty-space Folder Items Context Menu, targets the active tab's confirmed folder regardless of selection, and opens the inline New Folder Name Editor. The New Folder Name Editor is an empty temporary row pinned at the top of the listing. A name collision, a name containing only whitespace, a name that is too long, or characters the volume rejects keep the corresponding editor open with an error, without overwriting or creating an Item. Return or focus loss commits; if such a name problem arrives after focus loss, the editor reopens on its row with the typed name and the error. Other failures close the editor and show the job's Operation Decision Card. Committing an unchanged name closes the editor. A successful edit closes the editor, refreshes affected open tabs, and selects the new or renamed Item.
- Move to Trash uses `Command+Delete` or the Folder Items Context Menu. Delete Permanently uses `Option+Command+Delete` or that menu. Both require one or more selected Items and a confirmed source folder, and capture the selected targets when invoked; later selection or tab changes cannot retarget them. Delete Permanently opens a separate Permanent Delete Confirmation Window showing only the frozen target count. Cancel is the default; deletion requires explicit activation of Delete Permanently.
- Activating exactly one macOS package opens it with its default application; Show Package Contents in the Folder Items Context Menu, with no default shortcut, navigates into it. Activating a link to a package opens its target. Copy and Move act on the package or link itself.
- Activating exactly one regular file opens it with the default application. Activating a link to a regular file opens its target with the default application; Copy and Move act on the link. A link to a folder follows the [navigation rule](product-behavior.md#file-operation-safeguards). File activation requires a confirmed source folder. An opening failure appears in Notices, which opens to show it.
- While an inline name editor has keyboard focus, text editing takes priority and every workspace shortcut except `Command+Q` is suppressed until editing ends. Quitting discards the draft.
- Open Item, Copy to Other Browser, Move to Other Browser, Rename Item, Move to Trash, and Delete Permanently shortcuts act only while the Folder Items List has keyboard focus; New Folder works anywhere in the workspace window.
- While a file operation runs, its temporary artifacts use a reserved name pattern; Folder Items never lists those created during the current launch. If the displayed folder, or a folder above it, is renamed, moved, trashed, or deleted, the Browser keeps its last successful rows and path, dims the rows, and shows the Missing Folder Overlay, the text “Command+R to Refresh” centered in the Folder Items area, until a refresh succeeds. The narrow-Browser `Expand` overlay takes precedence. Quitting or closing the window while operations run asks for confirmation; Quit cancels them with cleanup and Cancel keeps them running.
- In P3-M8, disabled file-command menu items stay disabled. If a person invokes an unavailable file-command shortcut, its source Browser Status Bar briefly shows the reason for about three seconds, then resumes its current loading, error, or path text.

### Quick Look

- With keyboard focus in a Folder Items List, plain Space captures its cursor row. The cursor is used even when it is not selected or when another row is selected. No cursor, a modified Space, and an auto-repeat Space are no-ops. Files, folders, packages, and links are all given to macOS; Dual Pane does not resolve links or decide previewability.
- Releasing Space before 256 ms opens the native Quick Look Panel at its normal system size for normal controls and dismissal. Holding it for 256 ms opens the panel at the largest usable frame on the workspace's current screen; the menu bar and Dock remain available. The first visible frame is already full sized, revealed by a brief AppKit opacity transition or immediately when Reduce Motion is enabled. The held panel stays at the usable frame if a provider tries to resize it. Releasing that held Space dismisses it. If no usable screen frame is available, the normal sized panel opens until release.
- Switching to another application or an unrelated window, or losing Quick Look panel control while Space is held, dismisses the panel. The expected transfer from the workspace window to its Quick Look Panel does not count as an interruption. The panel has no saved geometry and does not change Folder Items selection, cursor, location, tabs, or focus state behind it. A failure to acquire or present the system panel briefly reports in the source Browser Status Bar; a format macOS cannot preview remains macOS-owned feedback.

### Operation Panels and decisions

- A job that outlasts a brief reveal delay, needs a decision, or reaches a failed or partial result shows its own floating Operation Panel with progress and a Cancel Operation Button. A panel can be dragged into the Operation Panel Strip below both Browsers; docked panels arrange left to right. Docking and undocking have no keyboard command. A running or decision-waiting panel stays open. Closing its source Browser Tab does not cancel the job; `Command+W` does nothing while a running or decision-waiting panel has focus.
- A job's conflict or recoverable-error choices appear in its Operation Decision Card. Several jobs may show decision cards simultaneously. A card never takes keyboard focus and has no default button; it is announced for accessibility. Floating Operation Panels join macOS window cycling (``Command+` ``), and docked panels are in the workspace window's Tab order. The [file-operation safeguards](product-behavior.md#file-operation-safeguards) define the choices and the initially unchecked, conflict-only “apply to all” option.
- A successful panel hides about three seconds after completion. A clean cancellation with no completed changes hides after the same delay; cancellation with completed or uncertain work, and partial or failed results, remain for review. `Command+W` closes a completed panel while it has focus, docked or floating. Quick successes are recorded in Notices without opening it; quick failures open Notices to show the error. Cancellation leaves completed work intact under the [file-operation safeguards](product-behavior.md#file-operation-safeguards).

### Notices and restoration feedback

- Notices is an auxiliary window for nonblocking messages. Its Notices Button in the Main Toolbar is a local bitmap icon button, with tooltip and accessible name, and reopens it. Settings and Notices sit together without a gap in a borderless toolbar box at the bottom-left of the Sidebar, inset from the left edge; both are compact bitmap controls. The Notices Startup Checkbox is default-unchecked and shows “Don’t show notices at startup”. `Command+W` closes Notices while it has focus. The [session recovery policy](product-behavior.md#session-recovery) defines startup opening, message suppression, session lifetime, and tab fallback.
- P3-M6 shows storage and Favorite target-probe errors in Notices. Rejected Favorite name edits show an inline error without adding a Notice. When a completed launch probe removes an unavailable Favorite Item, Notices names the removed Item. An actionable storage failure opens Notices, including at launch, and offers Reset Settings with explicit confirmation and a visible outcome. The [settings storage contract](archive/phases/phase-3/milestone-02-architecture.md#storage-and-lifecycle) defines what reset preserves. Operation and restoration messages arrive in their later milestones.
- At relaunch, each Browser shows its saved tabs and active tab at once, and the restored active Browser's Folder Items List has keyboard focus. Each restored tab reads its folder, the active tab first. A tab whose read finds its location unrestorable under the [session recovery policy](product-behavior.md#session-recovery) leaves the Browser Tabs Strip when that result arrives, and a Notice names its folder and the reason.
- At relaunch the workspace window waits for the settings-load answer for up to ten seconds, then appears once at its saved frame and zoomed or full-screen state, with the Sidebar Splitter and Browser Divider where they were. A slow load shows a separate, transient Waiting Window with a polished, indeterminate dark animation, a “Loading workspace” label, an accessible status, reduced-motion support, and Quit; it closes as the workspace appears. On timeout, the workspace opens at the default layout with Home tabs and a storage timeout Notice. A late load never moves the visible workspace or replaces its tabs; this launch's session changes are not saved. Full screen reopens in its own Space.
- The Reset Settings confirmation says that open tabs close and the window layout returns to its defaults. After a successful reset, the window leaves full screen or zoom and takes its default size, centered on its current display.
- The startup period ends when the settings load, restored-tab reads, Favorite launch probes, and temporaries sweep have answered, or about five seconds after the workspace window appears, whichever comes first. With the Notices Startup Checkbox unchecked, the first startup notice recorded during that period opens Notices once, without taking focus. The [session recovery policy](product-behavior.md#session-recovery) defines what the checked box suppresses.

### Automatic refresh

- Inactive Browser Tabs refresh in the background. During an active-tab refresh, keep the last successful Folder Items visible with a small status cue. A newer navigation, sort, or refresh request takes precedence over an older result. Once a new listing succeeds, retain matching selected Items and cursor; drop Items that disappeared, clear a missing cursor instead of moving it onto another Item, and retain scroll position as closely as possible. A failed refresh leaves the last successful view and path available with error feedback. If the watched folder disappears or becomes inaccessible, keep that view and path with an error; retry on `Command+R` or a later file-system event without automatically navigating to a parent. `Command+R` is the only manual Refresh entry point. After an operation changes a folder, refresh every open tab showing an affected folder, including inactive tabs in either Browser.

## Phase 4 interaction decisions (planned)

- A name filter matches substrings of displayed Item names in the current folder using full Unicode case folding and accent-insensitive matching. Leading and trailing query spaces match literally; only an empty query shows every Item. A filename with invalid UTF-8 can match its displayed replacement characters; actions still use its exact bytes, so distinct names never become the same Item. Its text belongs to the Browser Tab: switching tabs keeps it, while any successful change to a different confirmed folder, including Back or Forward, clears it. Failed navigation, same-folder refresh, and sort keep it; relaunch resets it. An Item hidden by the filter leaves selection and cursor state, and a hidden range anchor clears. When filtering hides the top visible Item, scroll to the nearest surviving Item in the prior sort order without selecting it; keep the prior pixel offset only if that Item remains visible. The summary shows visible matches out of the folder total, with selection count and size limited to visible Items. While the filter updates, the list clears with an updating cue; underlying visit state stays intact, and Item and selection-dependent actions wait for the result. A no-match state differs from updating or an empty folder. [P4-M2](phase-4/milestone-02-overview.md#owner-decisions) records the decisions; [P4-M3](phase-4/milestone-03-overview.md) owns the control and exact feedback wording.
- File Copy publishes the complete selection, including multiple files, folders, packages, and symbolic links, in a macOS clipboard representation that Finder can paste until the clipboard is replaced, even after Dual Pane quits or relaunches. File Copy from Finder can be pasted into Dual Pane and uses its safe Copy workflow; the Finder sources stay in place. Copy, Cut, and Paste also transfer files within Dual Pane. Cut does not promise a Finder move. A same-folder Paste is rejected with an explanation. After a started Cut Paste reaches a terminal result, the pending move clears; retrying remaining sources requires another Cut.
- File drags stay within Dual Pane. Either Browser's confirmed folder, folder rows, and Browser Tabs accept drops. An accepted drop moves by default; Option copies. The existing file-operation decisions and safeguards govern a Paste or accepted drop; remaining gestures and feedback are under [P4-M1 review](phase-4/milestone-01-overview.md).
- Typed path entry accepts absolute, `~/` home-relative, and paths relative to the submitting tab's confirmed folder. A failed submission keeps its typed text with an error. Escape, focus loss, or switching tabs discards an unsubmitted draft. Remaining path feedback and visual navigation rules are under [P4-M1 review](phase-4/milestone-01-overview.md).
- `Command+F` focuses the Folder Items Filter Control and `Command+L` edits the path. With Folder Items List focus, `Command+C`, `Command+X`, and `Command+V` perform file Copy, Cut, and Paste. Focused text editors keep ordinary text Copy, Cut, and Paste behavior.
- With a Folder Items List focused, typing unmodified printable text such as `g` starts that tab's filter and focuses the filter field for continued typing. Space retains Quick Look; movement, activation, and modified shortcuts keep their existing behavior. The owner will decide how the first character interacts with an existing query and text composition when [P4-M3](phase-4/milestone-03-overview.md) is planned for implementation.
