# P4-M14: Repair Folder Items Context Menu gestures

Status: Active

This milestone restores the Normal and Comprehensive Folder Items Context Menus for physical macOS secondary gestures, including a MacBook trackpad two-finger tap. It isolates the native gesture regression introduced during P4-M12, then verifies real pointer input as well as the existing menu policy. The [architecture plan](milestone-14-architecture.md) records the suspected root cause and repair sequence.

## Scope

In scope:

- Physical two-finger secondary tap and click, mouse secondary click, and exact Shift-secondary gestures on Folder Items rows and empty list space in both Browsers.
- Control-primary click and drag coexistence with the P4-M12 press/threshold rule.
- Native event classification, duplicate-menu prevention, selection timing, menu request delivery, and focused disposable-profile checks.

Out of scope:

- New menu actions, changes to the Normal or Comprehensive configurations, menu layout, persistence, or application-owned action availability and stale-target rules.
- Changing the file-drag operation policy or accepting external drags.

## Reported failure and current evidence

The owner reports that a MacBook trackpad two-finger tap opens neither the Normal nor the Comprehensive menu. P4-M10 previously passed guided macOS pointer acceptance. P4-M12 then added a native-event check to `FolderItemsList::contextMenuEvent`: a mouse context request is accepted and silently returned when AppKit's current event looks like a primary press or release, or a remembered remapped primary press is active. That is the only newly added early exit before the menu handler; the right-button mouse path does not open a menu itself. The same M12 change can classify a Qt right-button press as a remapped primary solely from AppKit's current event. This is the leading code-level regression site, not yet proof of the exact event sequence generated by this trackpad.

The existing offscreen Context Menu check injects `QContextMenuEvent` directly without a controlled native secondary event. The M12 drag check simulates a remapped primary sequence and checks that it does not open a menu. Neither check proves what the user's physical two-finger tap delivers or exercises a genuine native secondary sequence through the new guard.

## Sequence

P4-M14 is a focused repair before P4-M13 implementation and before closing P4-M12/P4-M7 physical-pointer acceptance. The shared gesture boundary must work before those acceptance results can be trusted. No P4-M13 application or persistence design changes are required by this work.

## Implementation evidence

On 2026-10-23, the repair replaced the ambient-AppKit-event early exit with suppression state that is created only when Folder Items observes a physical Control-primary press presented by Qt as a right-button press. A true secondary press clears that state, so a subsequent Qt context event continues through the existing menu coordinator even when AppKit's ambient current event reports a primary event. The source remains one menu route: no fallback menu is constructed from mouse press.

The disposable native checks now send secondary press, context, and release events to actual Folder Items viewports in both Browsers. They cover rows and empty space; Normal, exact-Shift Comprehensive, and Shift-plus-Control Normal classification; a deliberately primary ambient event during a genuine secondary context request; Control-primary suppression before and after release; suppression reset by either a true secondary or unrelated primary press; and drag-root preservation. `scripts/check-folder-items-context-menu.sh`, `scripts/check-file-drag-drop.sh`, and `make check` passed on 2026-10-23.

Physical pointer acceptance remains open.
