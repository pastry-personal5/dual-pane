# P4-M8 architecture

Status: Done

The navigation row renders the active tab's confirmed location as breadcrumbs and provides a separate Edit control that enters the P4-M6 path-entry mode. An Expand/Collapse control reveals columns of visible child-folder choices along the confirmed ancestor trail, ending at the current folder's parent. The [overview checklist](milestone-08-overview.md#completion-checklist) defines acceptance; M1 fixes collapse-after-selection, while M8 records the remaining owner decisions.

## Modes and ownership

The active Browser Tab's confirmed `Location` is the single source of truth for breadcrumb components and selected child rows. The Qt desktop owns visual expansion, the visible column window, hover, and text-editor draft; the application owns tab navigation, history, request identity, and the outcome of a submitted target. A breadcrumb or folder-row click carries the exact target `Location`, not an elided label or a string assembled from visible component names. It also carries the Browser, observed Tab ID, confirmed-path revision, and column generation when applicable. The application rejects a gesture if any observed identity has changed; it never redirects the target to whichever tab is active when delivered. An accepted gesture uses the ordinary `Navigate` read and history behavior, without parsing text through M6 `SubmitPath`. Only a successful navigation makes a new path confirmed. Clicking the already-confirmed breadcrumb is a no-op. Columns end at the current folder's parent and show the current folder as the selected child; they do not list its children.

Keep three presentation modes coherent: collapsed breadcrumb, expanded ancestor columns, and typed-path editor. The confirmed path determines the parent columns and selected rows; worker reads provide eligible sibling folders. Expanded state is per Browser and is not restored after relaunch. Disable Expand at `/`, which has no ancestor parent, and collapse if a newly confirmed path is `/`. Selecting a folder collapses immediately, starts ordinary navigation, and marks the target as pending in the breadcrumb without replacing the confirmed path. A failed navigation preserves the confirmed path and Folder Items. Entering typed-path editing collapses the columns and uses the existing M6 draft, cancellation, and tab-switch rules. Keep the M6 `PathEditControl` as the editor and preserve its `EditPath` shortcut, availability, feedback, and accessible name. Render breadcrumbs as separate display controls, so activating one cannot accidentally focus the editor; the new Edit button calls the existing edit transition.

## Folder-option requests

Enumerate immediate child folders only for the ancestor parents whose columns are visible at the current Browser width. Widening the Browser requests newly visible columns; narrowing it cancels reads for columns that disappear. Return exact native paths plus only the metadata needed to identify navigable folders. A request includes Browser, Tab ID, exact parent `Location`, item-visibility policy, and a generation tied to the expanded view and confirmed path. The application/desktop join the results with the confirmed path to identify the selected child; the worker does not decide selection. Keep request count and payload size bounded per Browser, use the existing read-lane admission/backpressure rules, and do not let column reads starve ordinary Folder Items reads. Collapse, tab switch, path change, or a newer generation invalidates old requests; late results cannot repopulate the control. Retry creates a new generation.

Apply current item-visibility settings to siblings. A folder already on the confirmed path remains visible and selected even if those settings would hide it; hidden siblings are omitted. Include symlink entries that resolve to navigable folders, but do not offer packages. Preserve M6 behavior for package and symlink path components already in the confirmed trail and use exact stored names and targets. Root, repeated names, symlinked folders, packages, unreadable parents, visibility changes, and undecodable path bytes need explicit tests. Each column has loading, empty, and retryable failure states; failures do not disturb the confirmed path or Folder Items. A stale row activation is revalidated by ordinary navigation before commit.

## Desktop composition and verification

Place the path display and typed editor in Folder Pane Toolbar Row #1, which `Browser` and `FolderPane` in `crates/dual-pane-desktop/cpp/include/dual_pane_desktop/folder_pane.hpp` compose, with accessible breadcrumb controls, an Expand/Collapse button, an Edit control, and a vertically expanding ancestor-column area directly below the row. Reuse the existing dark Browser surface, focus indicator, and splitter conventions; the fixed maximum height leaves the Folder Pane usable. At narrow widths, calculate how many columns fit at the minimum usable width and show that many, starting with the columns nearest the current folder. Do not scroll to or focus hidden columns; their ancestor targets remain available through breadcrumbs. If a resize hides the focused column, move focus to the nearest visible column without navigating. Expansion and collapse use a short animation, disabled when reduced motion is enabled. Within a column, Up/Down move through rows; Left/Right switch between visible columns; Return activates the selected folder; Escape collapses and returns focus to Folder Items List. Keep accessibility announcements precise; text entry shortcuts retain the M6 editor behavior.

Keep Qt model and widget changes on their affinity thread. Qt-free tests prove exact breadcrumb targets, token rejection, and tab-local navigation. Native checks verify pointer targets, keyboard and VoiceOver access, two-Browser isolation, per-column loading/empty/error/retry feedback, layout at supported widths, path-editor transitions, hidden confirmed components, and cancellation of stale column reads using a disposable profile and temporary directories. Avoid requiring filesystem features the test volume cannot represent (for example, non-UTF-8 names on APFS); report platform-specific limits precisely.
