# Phase 4 changelog

Status: Active

Chronological record of planning, owner decisions, and design changes for Phase 4. Newest entry first.

## Entries

- 2026-10-18 — Owner shortcut direction — Added `Command+Forward Delete` as a Move to Trash factory shortcut, after `Command+Delete` and before the Shift+Backspace and Shift+Forward Delete alternatives. Settings schema 10 gives it to an existing profile only when Move to Trash still has the prior three-shortcut factory list and no other action holds `Command+Forward Delete`; the schema 9 step now writes its own list explicitly, so later defaults cannot change it. A review of every shortcut found one more Command and Control swap from `6f28dee`: the fixed Settings shortcut was registered as Qt `Meta+,`, so v3.0.0 opened Settings with `Control+,` instead of `Command+,`. It now uses Qt `Ctrl+,`, and `scripts/check-settings-window.sh` pins it. The Keyboard Shortcuts editor sizes Shortcuts for its longest label, which ends in Forward Delete rather than Backspace.

- 2026-10-18 — P4-M5 milestone review — Owner clarification: clipboard replacement, a newer Copy or Cut, or the move ending clears the pending-Cut cue even while that Cut's Paste runs, so the cue shows only the Cut the clipboard holds now. This supersedes the earlier review entry that merged every started Cut into the cue. Paste Items is disabled when the clipboard holds only private data that is not this launch's current, unreserved transfer, such as a Cut from before a relaunch or one already pasted; a keyboard Paste still reports the reason. A read the clipboard worker could not take reports a busy clipboard instead of a replacement. The pasteboard adapter tags a write with the generation `clearContents` returned and reads items only within one unchanged generation, so a concurrent write by another application is never taken as Dual Pane's or mixed into a snapshot. Shortcut capture has a pure decode with a test pinning Command and Control; the swap it fixes arrived in `6f28dee`, so the v3.0.0 release shipped with Command shortcut defaults that answered only to Control. The native-checks item is open again: cancellation of a running Paste was never run, and the first replacement failure is unexplained. `scripts/clipboard-acceptance.sh` adds `context-menus`, `text-editor-focus`, and `cancel-running-paste` scenarios. It now uses the temporary folder as the profile's Home, launches with the Left Browser at the source, empties staged folders in place, and refuses a replacement run whose Paste came first. See [acceptance evidence](milestone-05-overview.md#acceptance-evidence).

- 2026-10-18 — P4-M5 native checks — The owner ran the guided Finder clipboard acceptance: Copy and Paste in both directions for files, folders, packages, and symbolic links, before and after relaunch, Cut and Copy across Browsers, conflict Cancel, Cut expiry, and non-file content passed. Clipboard replacement failed once and then passed in a dedicated `scripts/clipboard-replacement-check.sh`; the first failure is unexplained. The acceptance script now keeps its summary after exit. Shortcut and menu behavior and focus separation remain open. See [acceptance evidence](milestone-05-overview.md#acceptance-evidence).

- 2026-10-18 — P4-M5 fix — Command shortcuts did not fire, including Command+C, X, and V. Qt on macOS reports Command as `ControlModifier` and Control as `MetaModifier`, but key-sequence generation and shortcut capture treated Meta as Command, so a default registered as `Meta+C` answered only to the Control key. Both now use the Qt names (`Ctrl+` for Command, `Meta+` for Control). A custom shortcut recorded earlier was stored with Command and Control reversed and must be set again.
- 2026-10-18 — P4-M5 fix — Paste from the menu or keyboard did nothing, for Finder and Dual Pane content alike: the desktop wrapped it as an observed command, and the workspace drops observed commands that name no visible target. Paste now submits as a plain command, since it targets the confirmed folder rather than visible rows.

- 2026-10-18 — P4-M5 review — A Paste whose read finds an unreported clipboard replacement now adopts the newer generation, so the retry reads current content instead of being rejected again. The pending-Cut cue covers the current Cut and every started Cut instead of one arbitrary running Cut. Keyboard Copy, Cut, and Paste observe the clipboard first, as the context menu does.

- 2026-10-18 — Command-line launch — `dual-pane <folder>` and `dual-pane <file>` show the folder in the Left Browser (activating an existing tab on it, else opening one) and select the file; strict argument errors; `make install` links `~/.local/bin/dual-pane`; each launch starts a new instance. See [Command-line launch](../product-behavior.md#command-line-launch).

- 2026-10-18 — P4-M5 implementation — Added the macOS clipboard adapter on a serialized lane, the Copy Items, Cut Items, and Paste Items actions with Folder Items Context Menu entries and list-scoped Command+C/X/V, pending-Cut cue and count, and brief feedback. Implementation rulings: file URLs are built and parsed as percent-encoded `file://` text rather than through `NSURL` filesystem representations, which could not carry invalid UTF-8 bytes and re-decomposed precomposed names; the Cut cue lasts until terminal consumption rather than clearing at Paste start; a publication stays valid unless a newer generation was observed, so observing Dual Pane's own write early no longer discards it; the cue count is the number of captured roots, shown where one matches and below refresh-monitoring notices; a cue change repaints rows in place. Native checks remain open pending the owner; see [acceptance evidence](milestone-05-overview.md#acceptance-evidence).

- 2026-10-18 — P4-M5 owner decisions and plan revision — Copy Items, Cut Items, and Paste Items are Folder Items Context Menu commands with list-scoped Command+C/X/V shortcuts; Paste targets the active confirmed folder. Pending Cut mutes exact path-and-kind row matches across visible tabs, adds accessible wording, and supplies low-priority persistent status. Clipboard replacement is silent while command preparation and attempted Paste receive brief specific feedback. Transfers preserve frozen paths; missing, renamed, or kind-changed roots reject, while supported same-kind content changed in place is scanned normally. A valid private token wins, but stale or unknown private data may fall through to colocated file URLs as safe external Copy. Finder acceptance automation is opt-in because it replaces the global clipboard.

- 2026-10-18 — P4-M4 completion and review — Added the Qt-free clipboard state machine with generation-, request-, and transfer-tagged transitions; observed byte-exact selection capture; private Copy/Cut and typed Finder snapshots; frozen Paste destinations; repeated Copy, Cut reservation, terminal consumption, and bounded cleanup of superseded transfer state; asynchronous no-follow all-or-nothing Finder preflight; and typed rejections. Generalized the operation model and existing scan, lane, execution, conflict, presentation, safety, and refresh paths to arbitrary mixed-parent roots without changing direct Copy/Move commands. Race, validation, mixed-root, symlink, and compatibility tests pass; direct Rust gates and `make check` pass.

- 2026-10-18 — P4-M4 owner decisions — Copy remains reusable until clipboard replacement and may start overlapping independent Paste operations. A Cut rejected before a job starts remains pending; a started Cut is reserved and consumed at every terminal result. Paste requires a ready, successfully loaded destination tab. Finder sources receive an asynchronous, no-follow, all-or-nothing preflight, so any malformed, duplicate, unavailable, or unsupported root rejects the Paste before an operation starts.

- 2026-10-18 — Plan review — Expanded the P4-M4 plans with an explicit owner-decision record, a generation- and request-tagged clipboard state machine, mixed-parent Finder source roots, Cut reservation and terminal consumption, concrete module boundaries, sequencing, and race-focused acceptance coverage. No owner-visible behavior was decided by this review.
