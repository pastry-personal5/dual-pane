# P4-M5 architecture

Status: Planned

The desktop translates macOS clipboard content and gestures into typed application inputs. The [overview checklist](milestone-05-overview.md#completion-checklist) defines acceptance; M1 requires file Copy and Paste between Finder and Dual Pane in both directions and fixes shortcut defaults. M5 planning settles menus and feedback.

## Desktop clipboard boundary

`crates/dual-pane-desktop/cpp/src/desktop_window.cpp` owns context-menu and key routing, and a desktop adapter owns pasteboard observation and conversion. Prefer the existing CXX-Qt bridge and `browser_session.rs` for typed commands and projections. On Copy, publish Dual Pane's private intent alongside a Finder-compatible file representation built from exact native source paths and independent of the app process's lifetime; on Cut, publish only the private intent. A Finder Paste of Dual Pane's Copy is performed by Finder, not by Dual Pane's operation engine. Paste into Dual Pane reads either a valid private intent or Finder-copied file references. The adapter converts external references into a typed, byte-exact source snapshot for application validation and safe Copy; it never treats an external reference as Cut. Private intent expires on app relaunch even if Finder can still use the file representation; Finder-copied references can still be pasted after Dual Pane relaunches while the clipboard is unchanged. Do not let a Qt clipboard object or platform MIME type leak into the application or domain crates. Clipboard reads that may contact an external provider cannot block a GUI turn; deliver their result as an event and revalidate the current clipboard generation before enabling Paste.

Add action IDs only by appending stable compatibility keys to the existing persisted catalog. Give the shortcut editor readable names, scopes, defaults, and conflict behavior from M1. When a text editor owns focus, its copy, cut, and paste stay text operations; Folder Items shortcuts require the approved Folder Items or workspace focus. The presenter owns disabled reasons, Cut indication, and paste result wording. Native checks must prove a Finder Paste copies temporary source files after Dual Pane Copy, including after the app quits or relaunches, leaves the sources unchanged, and does not create a Dual Pane operation. They must also prove that Copy in Finder followed by Paste into Dual Pane creates a safeguarded Copy of temporary files without altering Finder's sources, including after Dual Pane relaunches. Check clipboard replacement and rejection of malformed or non-file content without using real user files as operation targets.
