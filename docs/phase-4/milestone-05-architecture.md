# P4-M5 architecture

Status: Active

The desktop translates macOS clipboard content and gestures into typed application inputs. The [overview checklist](milestone-05-overview.md#completion-checklist) defines acceptance; M1 requires file Copy and Paste between Finder and Dual Pane in both directions and fixes shortcut defaults. M5 planning settles menus and feedback.

## Native pasteboard representation and ownership

The desktop owns one serialized Objective-C++ clipboard lane backed by `NSPasteboard.generalPasteboard`. The private pasteboard type is `org.dual-pane.private-transfer`. Its versioned payload contains only a format version and `TransferId`; it never contains a source path. Copy eagerly writes one file-URL pasteboard item per frozen root in clipboard order and places the private payload on the first item. Cut writes one item containing only the private payload. Eager file URLs let Finder keep using a Copy after Dual Pane exits, without a promised-data provider or persistence service.

The adapter writes and parses `file://` URL text itself, percent-encoding every path byte that is not unreserved, so an Item's exact name bytes survive the round trip. `NSURL`'s filesystem-representation calls were rejected after native tests showed that they cannot carry bytes that are not valid UTF-8 and that they re-decompose precomposed names. Display strings, Qt URLs, and decoded text are not source identity. A file reference URL (`file:///.file/id=…`), which Finder can offer, names no path until the system resolves it; the adapter resolves it and reads the result through the same codec, and refuses one that no longer resolves. It accepts only local `file://` URLs with an empty or `localhost` host, and it rejects a relative form, another scheme or host, a query or fragment, control characters, a bad percent escape, an encoded NUL, malformed tokens, unavailable representations, and unsupported content, without returning a valid subset. Duplicates are rejected by the application before preflight. Native adapter tests give the calling thread a unique pasteboard through an isolation seam, whose helpers refuse to run outside isolation, so they never disturb the general pasteboard.

Every publication result includes the native `NSPasteboard.changeCount` generation, including failure. If publication fails before native mutation, application state may retain the previously acknowledged transfer. If the generation changed before failure, the prior transfer is invalidated. The adapter observes generation at launch, on Qt clipboard-change notification, application activation, context-menu preparation, and every Paste request.

## Serialized asynchronous flow

Publication and reads run on the clipboard lane, never by synchronously materializing another application's provider data on the GUI thread. Results return through the existing application event boundary with request and generation tags. A read result is discarded if its generation is no longer current when delivered; external preflight is likewise discarded if the generation changes before it completes.

The cached native offer distinguishes private data, file URLs, both, and unsupported content. This cache is only an availability hint: Paste is enabled when the active destination is ready and the offer could contain supported content, then invocation observes the generation again and performs a fresh asynchronous read and validation. A snapshot can contain both a decoded private token and ordered file URLs. A current known private token takes precedence. An unknown or stale private token falls through only to valid colocated file URLs and therefore becomes an external Copy; Cut has no fallback representation.

## Application and presentation projection

The Qt-free application exposes clipboard availability and pending-Cut roots as ordinary model state. It does not expose `NSPasteboard`, UTI, Qt MIME, or widget types. Pending roots remain byte-exact `Location` plus captured kind values. Each Browser presenter projects a row as pending Cut only when both its exact path and kind match one of those roots, including when matching tabs are visible in both Browsers. Publication of a newer Copy/Cut, native replacement, or terminal Cut consumption clears the projection. Selection and focus remain visually authoritative over the muted text/icon treatment. The cue persists while a started Cut runs and clears only at the terminal result, replacement, or a newer Copy or Cut. A presentation change repaints the affected rows in place and changes nothing when the pending roots are unchanged, so a Copy never disturbs scroll or selection.

The low-priority status count shows the number of captured Cut roots, and only in a view where at least one row matches. Loading, error, filter, refresh-monitoring notices, and transient feedback take precedence, and the count replaces only the plain location text. Copy, Cut, and accepted Paste preparation receive brief acknowledgement. Clipboard replacement itself is silent. Rejections map typed reasons to specific text.

## Desktop command surface

`crates/dual-pane-desktop/cpp/src/desktop_window.cpp` owns context-menu and key routing. The selected-row Folder Items Context Menu begins with Copy Items, Cut Items, and Paste Items, followed by a separator and the existing direct other-Browser and file commands. The empty-space menu contains Paste Items, a separator, and New Folder. Paste ignores the clicked row and captures the active tab's confirmed folder.

Add action IDs only by appending stable compatibility keys to the existing persisted catalog. Give the shortcut editor readable names, scopes, defaults, and conflict behavior from M1. When a text editor owns focus, its copy, cut, and paste stay text operations; Folder Items shortcuts require the approved Folder Items or workspace focus. The presenter owns disabled reasons, Cut indication, and paste result wording. Native checks must prove a Finder Paste copies temporary source files after Dual Pane Copy, including after the app quits or relaunches, leaves the sources unchanged, and does not create a Dual Pane operation. They must also prove that Copy in Finder followed by Paste into Dual Pane creates a safeguarded Copy of temporary files without altering Finder's sources, including after Dual Pane relaunches. Check clipboard replacement and rejection of malformed or non-file content without using real user files as operation targets.

## Source validation and operation handoff

The private transfer retains the roots captured by Copy or Cut; external snapshots preserve Finder's order. Paste retains the destination captured at invocation. Neither a rename nor a changed selection is followed or recaptured. External preflight uses no-follow metadata and is all-or-nothing. A missing root or a root whose no-follow kind changed is rejected. Content that changes while its path and supported kind remain the same is scanned and operated on in its current state. The existing scanner remains the final identity check and the existing conflict, progress, cancellation, journal, partial-outcome, refresh, and verified-before-removal paths remain authoritative.

## Verification

Qt-free tests cover action-catalog migration and conflicts, offer/snapshot precedence, publication ordering, delayed reads, pending-Cut projection, and frozen changed-source behavior. Native adapter tests cover multiple roots and root kinds, mixed parents, arbitrary path bytes, malformed tokens and URLs, eager representations, generation races, order, and absence of paths from private payloads. Desktop tests cover menu order and availability, focus routing, target capture, muted/accessibility presentation, status priority, and matching views.

The opt-in `scripts/clipboard-acceptance.sh` sits outside `make check`. It is guided: the operator performs each gesture in Dual Pane and Finder, and the script stages fixtures and verifies content hashes, symbolic-link targets, and unchanged sources; `--self-test` exercises only its fixture and verifier logic. It warns before replacing the global clipboard, uses a disposable Dual Pane profile and temporary source/destination folders, and covers outbound and inbound single/multiple files, folders, packages, links, quit/relaunch, unchanged sources, replacement, malformed/non-file input, conflicts, cancellation, private expiry, and the absence of Finder move export for Cut.
